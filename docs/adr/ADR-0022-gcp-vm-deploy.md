# ADR-0022 — 운영 배포: GCP VM 한 대에 Docker Compose (비용 최소)

- 상태: `실험 중`. 첫 운영 구성이다. 실제 메모리·비용을 재고 나서 다시 정한다.
- 작성일: 2026-11-14, 개정 2026-11-15(Render 무료 데모안 → GCP 운영안)
- 근거: ADR-0004(RLS), ADR-0005(작업 큐), ADR-0006(RLS 밖 저장소), ADR-0013(같은 출처 쿠키 세션), ADR-0016(Google 로그인·연결, 데이터 키), ADR-0019(메일 색인), ADR-0021(알림)
- 사실 확인: GCP 무료 등급·Cloud SQL 확장 문서(2026-11-15). 유료 가격은 공식 가격 페이지를 읽지 못해 계산기로 확인할 항목으로 남긴다.

## 문제
12단계는 실제 운영 배포다. 메일 색인·알림 동기화를 포함한 모든 기능이 항상 돌아야 한다. 개발자가 GCP에 한 번 충전해 둔 크레딧(4만 원)이 예산의 전부라서, 매달 나가는 비용을 최소로 해야 한다.

## 검토 경과
- Render 무료(메모리 512MB, 15분 절전, 워커 없음): 측정한 최대 메모리 641MiB(Kiwi 형태소 분석기 로드 시)를 넘고, 절전 중 주기 작업이 멈춰 운영에 맞지 않는다.
- Neon 무료 DB: 선행 확인은 통과했지만(Postgres 18.7, pgvector 0.8.7, SQL로 만든 역할은 `BYPASSRLS` 없음, 직접 연결에서 `LISTEN/NOTIFY` 동작) 워커가 항상 연결해 있으면 일시 정지하지 못해 월 100 CU-시간을 넘기 쉽다. 쓰지 않는다.
- Cloud SQL: pgvector 0.8.5를 지원하지만 VM과 별도로 매달 비용이 든다. 비용이 문제가 되지 않을 때의 이전 대상으로 남긴다.

## 결정

### 1. 구성
- GCP Compute Engine VM 한 대에 Docker Compose로 다음을 올린다: Postgres 17 + pgvector(로컬·CI와 같은 이미지), Orbit 앱, Caddy(HTTPS 종료와 인증서 자동 발급).
- **1단계: 무료 e2-micro**(미국 us-west1, 표준 디스크 30GB까지 무료). 메모리가 1GB라 다음을 함께 적용한다.
  - 앱은 API와 워커를 한 프로세스로 띄운다(`ORBIT_EMBEDDED_WORKER=true`, 이미 구현됨). Python 기본 메모리를 한 번만 쓴다.
  - Kiwi를 가볍게 설정하고(`num_workers=1`, 다중어 사전 미로드) 처음 쓸 때 불러온다. 측정값 약 340MiB(기본 525MiB). 토큰화 결과가 달라질 수 있으므로 로컬·평가·운영이 같은 설정을 쓴다(상수 한곳).
  - 스왑 2GB, Postgres 메모리 설정 축소.
- **2단계(필요할 때만): e2-small(2GB)로 머신 유형 변경**. 메모리 부족으로 앱이 반복 종료되거나 응답이 느려지면 VM을 멈추고 머신 유형만 바꾼다(디스크·주소 유지). 이때부터 크레딧이 소진된다. 이 판단은 1주 이상 메모리·스왑 사용량을 보고 한다.
- 지역이 미국이라 서울에서 왕복 지연이 늘지만, 응답 시간의 대부분은 LLM 호출이라 받아들인다(측정 전).

### 2. 비밀값과 키 관리 (KMS)
- 비밀값(데이터 키 KEK, 세션 서명 키, Google 클라이언트 비밀, OpenAI 키, DB 비밀번호)은 VM 디스크에 **Cloud KMS로 암호화한 파일**로만 둔다.
- 앱 시작 스크립트가 VM 서비스 계정 권한으로 복호화해 메모리 파일시스템(tmpfs)에 권한 0600으로 풀고, 기존 설정(`ORBIT_DATA_KEY_FILE`, `ORBIT_SESSION_SIGNING_KEY_FILE` 등)이 가리키게 한다. 평문은 디스크·이미지·저장소에 남지 않는다.
- VM 서비스 계정에는 해당 키의 복호화 권한만 준다. 키 회전은 KMS 키 버전으로 한다(데이터 재암호화는 별도 작업).
- 비용: 키 하나와 시작 시 복호화 몇 번이라 매달 거의 들지 않는다(가격 확인 필요).

### 3. DB 역할과 격리
- 역할은 기존 `backend/db/init/00_roles.sql`과 같은 속성(`NOSUPERUSER NOBYPASSRLS`)으로 만든다. 앱은 `orbit_app`, 마이그레이션은 `orbit_owner`로만 접속한다.
- 시작 시 점검(이미 구현): prod에서 접속 역할이 superuser·`BYPASSRLS`·다른 역할의 멤버·RLS 테이블 소유자이면, 또는 DB 리비전이 코드와 다르면 시작을 거부한다.
- 마이그레이션은 배포 스크립트가 앱을 올리기 전에 일회성 컨테이너로 `orbit_owner` 접속으로 실행한다. 앱 컨테이너에는 `orbit_owner` 비밀번호를 주지 않는다.
- Postgres 포트는 VM 밖으로 열지 않는다(Compose 내부 네트워크만).

### 4. 네트워크와 HTTPS
- 방화벽은 80·443만 연다. SSH는 IAP 터널(공개 22번 포트 없음)로만 한다.
- Caddy가 Let's Encrypt 인증서를 자동 발급하고 앱으로 넘긴다. 앱은 Caddy만 프록시로 믿는다(`--forwarded-allow-ips`를 Compose 내부 주소로 한정).
- 도메인이 필요하다(Google OAuth 리디렉션 URI는 HTTPS 공개 도메인이어야 한다). 개발자가 가진 도메인을 쓰거나 새로 산다. 무료 와일드카드 DNS 서비스는 OAuth 등록 가능 여부가 확인되지 않아 기본안으로 두지 않는다.
- 접근 로그 쿼리 가리기(구현됨)를 Caddy 로그에도 적용한다.

### 5. 백업
- 매일 `pg_dump`를 Cloud Storage 비공개 버킷(미국 리전)에 올리고 7일 뒤 지운다. 덤프에는 메일 색인 본문이 들어가므로 버킷은 VM 서비스 계정만 쓸 수 있고, 덤프 파일은 KMS 키로 암호화한 뒤 올린다.
- 복구 절차를 문서로 두고 첫 배포 때 한 번 실제로 복구해 본다.

### 6. 배포 환경 안전장치 (구현됨, 이름만 바꿈)
- 배포 Compose는 `ORBIT_ENV=prod`를 고정하고 배포 표시 변수 `ORBIT_DEPLOYED=1`을 넣는다. `ORBIT_DEPLOYED`가 있는데 `ORBIT_ENV=dev`이면 시작을 거부한다(Render 전용 `RENDER` 변수 점검을 대체).
- prod에서 `ORBIT_LOGIN_ALLOWED_EMAILS`가 비어 있으면 시작을 거부한다. Google 앱 검증 전이므로 사용자는 OAuth 테스트 사용자 목록에도 넣는다.

### 7. 비용 (계산기로 확인할 항목)
| 항목 | 1단계(e2-micro) | 2단계(e2-small) |
| --- | --- | --- |
| VM | 무료 등급 | 유료(크레딧 소진) |
| 디스크 30GB 표준 | 무료 등급 | 무료 등급 |
| 외부 IPv4 주소 | 확인 필요(무료 등급 포함 여부) | 확인 필요 |
| 북미 밖으로 나가는 트래픽 | 월 1GB 무료, 초과분 과금 | 같음 |
| Cloud KMS·Cloud Storage | 소액 | 소액 |
| 도메인 | 개발자 부담(연 단위) | 같음 |

- GCP 예산 알림(예: 크레딧의 50%·90%)을 설정한다.

## 보류
- 관측(로그·지표·추적), 다중 사용자·초대, Google 앱 검증과 제한 범위 보안 평가는 12단계의 나머지 작업이다.
- 관리형 DB(Cloud SQL), 서울 리전, 무중단 배포는 비용이 허락될 때 다시 본다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| Render 무료 + Neon 무료 | 메모리 512MB 초과, 절전 중 주기 작업 중단 |
| Render 유료 | 매달 비용이 들고 KMS가 없다 |
| Cloud Run + Cloud SQL | 항상 도는 워커에 맞지 않고(최소 인스턴스 비용), Cloud SQL 비용이 따로 든다 |
| Oracle Always Free VM | 메모리는 넉넉하지만 GCP 크레딧·KMS·OAuth 프로젝트와 따로 관리해야 하고, 무료 VM 확보·회수 조건이 불확실하다 |
| 처음부터 e2-small | 크레딧이 1~2개월 안에 소진될 것으로 추정된다. 무료 등급에서 먼저 재 본다 |
