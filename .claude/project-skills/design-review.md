# Orbit 보충 규칙: UI 디자인 검토

> `.claude/skills/design-review/SKILL.md`(하네스 스킬 팩 `ui-design`)에 Orbit 화면에만 해당하는 점검을 더한다. 둘이 충돌하면 이 문서가 우선한다. code-reviewer는 두 파일을 모두 Read로 읽는다.

## 검토 전에 읽을 것 (Orbit)
- `docs/brand/brand-guide.md`, `docs/brand/tokens.css` (브랜드는 채택 상태다)
- `.claude/project-skills/frontend-design.md` (Orbit 화면 규칙)
- 관련 ADR: ADR-0012(쓰기 경로, 승인·실행 기록, 출처 분류), ADR-0013(프론트엔드 스택, 쿠키 세션·CSRF)

## 중요도 보정
범용 점검표의 중요도에 아래를 더한다.
- **높음**: 외부 콘텐츠 렌더링 규칙(D6-1) 위반, 승인 없이 쓰기가 실행되는 것처럼 보이는 화면, 결과 불명 상태에서 "다시 보내기" 제공(D5-5), 클라이언트가 승인 인자를 다시 조립하거나 수정할 수 있음(D5-4).

## 문구 예시 (Orbit)
- 버튼 동사는 실제 동작으로: "메일 보내기", "일정 변경하기", "일정 취소하기". "확인", "승인", "제출"을 쓰지 않는다.
- 흐름 끝까지 같은 말: "메일 보내기" 버튼 → "메일을 보냈습니다" 알림. "전송 완료"처럼 바꾸지 않는다.
- 번역투 예: "발송 처리가 완료되었습니다" → "메일을 보냈습니다".
- 시스템 용어 대신 사용자 말: 워크스페이스 ID·실행 기록 → 내 계정·보낸 메일.

## 한글 조판·입력 보충
- 날짜·시각 표기를 한 형식으로 통일하고, **캘린더 화면에는 시간대**가 드러나야 한다(사용자 시간대 설정값 기준).
- 채팅 입력의 IME 가드는 `frontend/src/composer/useComposer.ts`의 `isImeEnter`를 쓴다. 새 입력창이 이를 거치지 않으면 지적한다.

## 영역 7(외부 콘텐츠 렌더링): Orbit은 항상 해당
메일·문서 본문을 보여 주므로 범용 점검표 7절을 항상 적용한다. 추가로:
- 메일 본문의 외부 이미지는 "이미지 표시" 같은 명시적 동작 뒤에만 불러온다. 자동 로딩이 하나라도 있으면 높음이다(열람 추적·유출 경로, D6-1).
- 링크는 실제 주소를 보여 주고, 표시 텍스트와 주소가 다르면 알린다.
- 외부 본문이 Orbit UI(버튼, 경고, 승인 문구)처럼 보이지 않도록 시각적으로 구분한다.
- 승인 대상 요약(`target`)의 제목도 외부 콘텐츠다. 텍스트로만 렌더링한다(ADR-0012 §4-1, `orbit.runflow.target`).

## 영역 8(프로젝트 전용 점검): 승인 화면과 쓰기 동작
보고 형식의 "프로젝트 전용 점검" 행 이름을 **"승인 화면·쓰기 동작"**으로 쓴다.
- **승인 화면에 보여야 하는 것**
  - 대상: 받는 사람 전체, 바꿀 일정, 대상 문서
  - 인자 요약: 제목, 본문 앞부분, 일시 변경 전후
  - 되돌릴 수 있는지: 메일 발송처럼 되돌릴 수 없는 동작은 `danger` 토큰과 문구로 명시
  - 외부 출처 경고: 받는 사람 같은 인자가 사용자 입력이 아니라 메일·문서 본문(`external_content`)이나 모델(`model`)에서 왔으면 그 인자 옆에 `warning`과 이유 한 줄을 표시한다(D6-1, ADR-0012 §2). 출처 정보는 서버 응답(`provenance`)에서 받아야 하고, 화면이 추측하면 안 된다. 출처 정보가 없거나 형식이 다르면 경고를 띄우는 쪽으로 처리한다(fail-closed).
  - 만료: 승인 유효 시간이 있으면 남은 시간을 보여 준다.
- 화면에 보이는 인자가 서버가 해시로 고정한 승인 인자와 같은 데이터인지 본다. 클라이언트가 인자를 다시 조립하거나 수정할 수 있으면 높음이다(D5-4, ADR-0012 §2).
- 위험 동작이 서버 승인 없이 실행 가능한 것처럼 보이지 않는다. 채팅의 전송은 승인 요청을 만들 뿐이고 쓰기 API를 직접 부르지 않는다. 서버가 실행을 확인하기 전에 "보냈습니다" 알림을 띄우지 않는다.
- 승인 대기 중에는 채팅 전송을 막는다(대기 중인 run이 있는데 새 요청이 섞이지 않게).
- 상태 표시가 승인 대기 / 실행 중 / 완료 / 실패 / 결과 확인 중(`unknown`·`needs_user`)을 구분한다. 결과가 불명확한 상태에서 "다시 보내기"를 제공하면 중복 발송이 생기므로 높음이다(D5-5, ADR-0012 §3).
- 승인 버튼은 처리 중 비활성화되고, 거절 버튼이 같은 무게로 보인다. 되돌릴 수 없는 동작에서 기본 포커스나 Enter가 승인으로 가지 않는다.
- 결정 API가 409를 돌려주면 다시 보내지 않고, `expired`(만료)와 그 밖(이미 결정됨)을 구분해 알린다(`frontend/src/approvals/useApprovalDecision.ts`).

## 브라우저 확인 (Orbit)
- Tab 키만으로 채팅 → 승인 화면 → 승인·거절까지 가 본다.
- 외부 이미지가 든 합성 메일을 열어 네트워크 요청이 생기지 않는지 본다. 실제 메일은 쓰지 않는다.
