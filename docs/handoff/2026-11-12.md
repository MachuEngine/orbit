## 3. 로컬 실행
```bash
docker compose -f backend/compose.yml up -d --wait
scripts/dev-run.sh migrate
scripts/dev-run.sh api            # 터미널 1 (기본 google 모드, sim이면 뒤에 sim)
scripts/dev-run.sh worker         # 터미널 2
scripts/dev-run.sh web            # 터미널 3 → 브라우저 http://localhost:5173 (127.0.0.1 말고 localhost)
```
- `secrets/.env`(로컬, 커밋 금지)에 필요한 변수는 `.env.example` 참고. `ORBIT_DATA_KEY_FILE`은 **절대 경로**.
- Google Cloud 프로젝트: 웹 OAuth 클라이언트, 리디렉션 URI 2개(`/api/auth/google/callback`, `/api/connections/google/callback`), Gmail·Calendar API 사용 설정, 테스트 사용자 등록 완료.

## 4. 작업 방식 메모
- 역할: 메인(설계·명세·판단·문서), implementer(코드), code-reviewer(읽기 전용). 수정·재검토 최대 2회.
- **Claude는 `secrets/`를 읽지 못한다**(권한 차단, 의도). 키가 필요한 실행은 개발자가 직접 하거나, 개발자가 허락하면 터미널 패널에서 `source secrets/.env`를 포함한 명령으로 실행한다. 출력에 키를 남기지 않는다.
- 비서 경로를 바꾸면 회귀 확인: `docs/pilot/README.md`의 명령으로 v0 dev를 luna(low)로 1회(약 0.04달러).
- 비밀정보 검사(gitleaks)를 **푸시 전에** 통과시킨다. 합성 테스트 값은 근거와 함께 `.gitleaksignore`.
- 리뷰어 훅은 worktree 안에서 git을 막는다(리뷰어가 diff 대신 파일을 읽음). 토큰 절약 차원에서 템플릿 개선 후보.
- 토큰 절약: 단계마다 새 세션으로 시작하고, 서브에이전트 보고는 짧게(하네스 v0.4.1).
- 단계 번호가 v0.2에서 바뀌었다. 옛 문서의 "7단계 RAG·8단계 Agent·9단계 운영"은 지금의 9단계 RAG·평가 보류(Agent)·12단계 운영에 해당한다.

## 5. 알려진 이슈 (7단계에서 처리)
1. 커넥터 오류가 모두 "연결 오류"로 표시된다(예: Calendar API 미사용 설정 `403 accessNotConfigured`).
2. 응답의 `#` 제목과 `[텍스트](주소)` 링크가 글자 그대로 보인다. 링크는 외부 콘텐츠에서 온 주소일 수 있어 자동 링크 대신 주소 노출 방식으로(D6-1).
3. `POST /api/runs` 응답 유실 시 재전송 중복(멱등 키 없음).
4. 로그아웃·만료 뒤에도 열린 SSE가 유지된다.
5. 워커가 로그를 거의 남기지 않아 실행 실패 원인을 DB에서 찾아야 했다.
6. 메시지마다 독립 처리(이전 대화를 모델에 넘기지 않음) → 8단계.
