# ADR-0031 — 평가 v1 기준 설정: luna + 메일 색인 검색

- 상태: 채택 (2026-11-17 개발자 결정: "luna + 색인")
- 작성일: 2026-11-17
- 근거: 평가 스위트 v1 비교 측정(ADR-0026·0028·0029·0030), ADR-0015(임시 고정 모델), ADR-0019(메일 색인)
- 개정 대상: ADR-0015의 "OpenRouter 연결 후 여러 모델을 비교해 다시 정한다"를 이 ADR로 마무리한다

## 측정 요약 (dev 88과제×3회, 독립 묶음 73, 기준: runflow_v0 react · luna · 색인 끔 = 0.49)
| 설정 | 성공률 | 기준 대비 짝 차이 [95% CI] | 성공 1건당 비용 |
| --- | --- | --- | --- |

| luna · plan_execute | 0.39 | −0.10 [−0.17, −0.03] | $0.0022 |

## 결정
1. **기준 모델은 `openai/gpt-6-luna`로 확정한다.** haiku는 성공률이 높지만 성공 1건당 비용이 약 5배이고, luna에 색인을 켠 설정과 성공률 차이가 작다(0.67 vs 0.64, 이 둘의 직접 비교는 하지 않았다). gemini는 성공률이 낮고 답할 수 없는 질문에서 환각이 많다(0.24).
2. **기준 설정은 runflow_v0 · react 패턴 · 메일 색인 검색 켬이다.** 이후 비교 실험(맥락·가드레일 등)은 이 설정 위에서 잰다. 결과에는 설정 지문(모델·추론 강도·색인 지문·패턴)으로 구분해 남긴다.
3. **추론 강도**: 기준은 `reasoning_effort=none`으로 유지한다. 후속 dev 88과제×3회 비교에서 low는 0.602, none(색인 켬)은 0.644이고 low−none은 −0.042 [−0.109, +0.020]으로 정확도 향상을 확인하지 못했다. low 본 실행 LLM 비용은 $0.197937, 사전 8건 포함 $0.204970이다(임베딩 비용 별도). low 선택 시 추론 항목 되돌리기가 자동으로 켜지고 코드 SHA·누적 토큰 상한 등 메타데이터 차이가 있으므로 세부 한계는 `docs/eval/results-v1.md`를 따른다. 실사용의 low 설정을 유지할지 none으로 바꿀지는 사용자 결정으로 남기며 이번 작업에서 실사용 설정을 바꾸지 않았다.
4. **패턴은 react를 유지한다.** fixed_workflow의 차이는 구분되지 않고(구간이 0을 걸침), test 실행에서 비결정적 정지가 있어 원인 확인 전에는 채택하지 않는다. plan_execute는 성공률이 낮다.

## 영향
- 실사용 경로는 이미 메일 색인 검색(ADR-0019)을 쓴다. 이 결정은 평가 기준 설정을 실사용 경로와 맞춘다.
- test 확인(130과제×1회·102묶음): luna 색인 켬 0.646, react 색인 끔 대비 +0.192 [0.100, 0.287]; haiku 0.577, +0.123 [0.031, 0.216]으로 dev의 양의 방향을 확인했다. plan·gemini·assistant는 같은 방향이지만 차이 CI가 0을 포함한다(`docs/eval/results-v1.md`).
- haiku + 색인 조합은 별도 검증 대상이며 low의 dev 결과는 결정 3을 따른다. test plan의 비용 미상 8건 때문에 기록 비용을 총 청구액으로 해석하지 않는다.
