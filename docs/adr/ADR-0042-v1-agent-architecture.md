# ADR-0042 — v1 Agent 아키텍처 확정 (대화 맥락·가드레일·음성 제외)

- 상태: 채택 (2026-11-24 개발자 결정)
- 작성일: 2026-11-24
- 근거: ADR-0030(Agent 패턴), ADR-0031(기준 설정), ADR-0035(RAG 검색 정책), ADR-0036~0038(RAG 아키텍처 비교), ADR-0039·0040(채점기), ADR-0041(v1 Agent Advanced 검색), [평가 결과 대장](../eval/README.md)

## 문제

평가 v1에서 모델·Agent 패턴·추론 강도·메일 검색 방식(RAG)·reranker를 비교했다. 결과가 ADR 여러 개에 흩어져 있고, 일부는 "평가 경로 전용"이라 제품에 무엇을 쓰는지 한곳에서 읽을 수 없다. 남은 평가는 대화 맥락(ADR-0032), 가드레일(ADR-0033), 음성이다. 이 셋을 뺀 제품 Agent 구성을 측정 결과에 근거해 확정한다.

## 결정

| 영역 | 확정 | 근거 (짝 차이는 cluster bootstrap 95% CI) |
| --- | --- | --- |
| 모델 | `openai/gpt-6-luna` | haiku + 색인은 test 0.762로 luna + 색인 0.708보다 높지만 dev 차이 +0.080 [−0.008, +0.170]은 CI가 0을 포함한다(C02). 성공 1건당 비용은 luna $0.0011, haiku $0.0072로 약 6.5배다. 개발자가 비용 대비 차이가 작다고 판단해 luna를 유지한다 |
| Agent 패턴 | ReAct (`runflow_v0`) | fixed_workflow +0.061(CI 0 포함, test 비결정적 정지), plan_execute −0.098(A01). 색인 켬 재비교에서도 기준을 유의하게 넘는 후보가 없었다(M02) |
| 메일 검색 | 색인 켬. Agent가 `search_indexed_mail`을 필요할 때 직접 부르는 Agentic RAG | 색인 켬 +0.155 [+0.072, +0.244](G01), test +0.192(T01). 고정 1회 검색·질의 재작성 정책은 기준과 차이를 확인하지 못했다(R02) |
| 검색 방식 | Hybrid(형태소 키워드 `ts_rank` + `text-embedding-3-small` 벡터, RRF k=60, 800자·100자 겹침 청크), 결과 그대로 반환 | ADR-0019 구성을 유지한다. 임베딩·청크·RRF 대안은 비교하지 않았다 |
| reranker·A2X | 넣지 않음(보류) | RAG 과제에서는 A2X가 가장 좋았지만(test 0.663, A2X−A2 +0.181 [0.108, 0.253], R03c), v1 Agent dev에서는 +0.015 [−0.027, 0.060]으로 차이를 확인하지 못했고 p95 지연이 12.7초에서 25.1초로 늘었다(ADR-0041). reranker 교체는 recall@5를 0.83 안팎에서 바꾸지 못했다 |
| 대화 맥락 | 현재 기본값 N=6(최근 원문 턴), K=20(참조 대상), M=30(읽는 과거 run), 오래된 턴은 요청 발췌 | ADR-0032 맥락 실험은 아직 하지 않았다. 지금 다중 턴 과제가 2~3턴이라 이 값의 경계를 재지 못한다. 실험 전까지 측정 없이 기본값을 쓴다 |
| 평가 채점 | 코드 구조 검사 + Jev v4 + Gemini 2차 판정 | ADR-0039·0040. 사람 대조 62건 중 61건 일치(C01) |

### 확정 구성의 성능 (ADR-0040 채점)

| 분할 | 성공률 | 비고 |
| --- | --- | --- |
| dev 88과제 × 3회 | 0.723 (`--max-steps 50`), 0.754 (`--max-steps 150`) | 두 숫자는 step 상한과 실행 시점이 다르다 |
| test 130과제 × 1회 (봉인) | 0.708 | C02 재판정 후 |

- 지연(dev, `--max-steps 150`): p50 5.5초, p95 12.7초.
- 남은 실패 중 가장 많은 유형은 `wrong_answer`다(dev 264에피소드 중 24건).

## 아직 정하지 않은 것

- 추론 강도: 평가 기준은 `none`, 실사용 설정(`.env.example`)은 `low`다. dev에서 low − none은 −0.042 [−0.109, +0.020]으로 정확도 차이를 확인하지 못했다(G02). 실사용을 none으로 맞출지는 개발자가 정한다.
- 가드레일 구성: ADR-0033 ablation 후 정한다.
- 음성 처리(STT 모델·흐름): 음성 평가 후 정한다.
- 대화 맥락 값(남은 평가): 긴 대화 평가 세트 24개를 만든 뒤 ADR-0032로 N·K·M과 오래된 턴 요약 방식을 정한다. 정확도와 토큰 비용·지연을 함께 본다.
- 검색 방식 세부(임베딩 모델, 청크 크기, RRF 값): 비교하지 않았다.

## 대안

- **haiku로 모델 변경**: test 성공률이 0.054 높지만 dev에서 차이를 확인하지 못했고 성공 1건당 비용이 약 6.5배다. 기각.
- **A2X(재작성 → Hybrid 20통 → reranker 5통 → 압축) 제품 반영**: ADR-0041에서 보류. 지연을 줄일 방법(GPU·API reranker)이 생기면 다시 본다.
- **ADR-0032 맥락 실험 후 확정**: 긴 대화 세트 24개를 새로 만들어야 하고 지금 세트로는 경계를 못 잰다. 이번 확정에서 빼고 남은 평가로 둔다.

## 영향

- 제품 코드는 바꾸지 않는다. 현재 실사용 경로가 이미 이 구성(luna · ReAct · 색인 켬 · Hybrid)이다. 추론 강도만 실사용 `low`, 평가 `none`으로 다르다.
- ADR-0031의 haiku 재검토는 이 ADR로 마무리한다.
- 이후 대화 맥락·가드레일·음성 평가는 이 구성 위에서 잰다.
