# Orbit 보충 규칙: 브랜드 정체성

> `.claude/skills/brand-identity/SKILL.md`(하네스 스킬 팩 `ui-design`)에 Orbit에만 해당하는 내용을 더한다. 둘이 충돌하면 이 문서가 우선한다.

## 1. 현재 상태: 브랜드는 확정됐다
- Orbit 브랜드는 2026-11-11에 개발자가 채택했다. 팔레트 C 흑연, 글꼴 IBM Plex Sans KR, 로고마크 A 게이트, 워드마크·조합형이다. 기준 문서는 `docs/brand/brand-guide.md`이고, 결정 이유와 기각안은 그 문서 끝의 결정 기록에 있다.
- 따라서 이 스킬을 쓰는 경우는 보통 **기존 결정을 바꾸거나 토큰을 추가할 때**다. 처음부터 후보를 다시 만들지 않는다. 바꾸기 전에 결정 기록을 읽고, 바꾼 이유를 같은 형식으로 추가한다.
- 브랜드 가이드의 "남은 일"(상표·유사 로고 확인, 숫자 모양·`tnum` 확인, 워드마크 커닝, 포커스 링 대비, OFL Reserved Font Name 확인)을 처리하면 그 항목을 갱신한다.

## 2. 산출물 위치
범용 스킬의 기본 경로를 그대로 쓴다: `docs/brand/brand-guide.md`, `docs/brand/tokens.json`, `docs/brand/tokens.css`, `docs/brand/logo/`, `docs/brand/preview/`. 프론트엔드는 `frontend/`에서 `docs/brand/tokens.css`를 불러온다(개발 서버 `server.fs.allow`에 `../docs/brand`가 있다).

## 3. Orbit 브리프 (브랜드 가이드 1절 요약)
- **사용자**: 메일·캘린더·문서를 많이 다루는 한국어 사용자. 비서에게 일을 맡기되, 외부로 나가는 행동은 직접 승인한다.
- **성격 키워드**(개발자 확정): 통제할 수 있다 / 미리 보인다 / 차분하다 / 정확하다. 승인 화면이 제품의 핵심이라 이 키워드가 나왔다. 브랜드를 바꿀 때도 이 키워드와 연결해 이유를 쓴다.
- **숫자·기호가 섞인 문자열**: 메일 주소, 날짜, 시각이 자주 섞인다. 글꼴을 바꾸면 이 문자열의 모양을 본다.

## 4. 의미 색 (Orbit에서 정한 매핑)
| 토큰 | 상태 | 근거 |
| --- | --- | --- |
| `info` | 일반 정보 | |
| `warning` | **외부 출처 경고**: 승인 인자(수신자 등)가 사용자 발화가 아니라 메일·문서 본문이나 모델에서 왔다 | D6-1, ADR-0012 §2 출처 분류 |
| `danger` | 되돌릴 수 없는 행동(메일 발송 등) | D5-5 |
| `success` | 실행 완료 | |
| `error` | 실패·오류 | |

- 공통 토큰: `bg`, `surface`, `text`, `text-muted`, `border`, `divider`, `accent`, `on-accent`, `focus`.
- `warning`, `danger`, `error`는 색만으로 구분하지 않는다. 아이콘과 문구를 함께 쓴다.

## 5. 로고
- "Orbit"에서 바로 떠오르는 행성 고리·궤도 원은 흔한 모양이라 기각했다. 로고를 바꿀 때도 이 방향은 다른 서비스 로고와 겹치지 않는지 특히 확인한다.
- 채택한 게이트 기호는 "요청이 승인 지점에서 멈춘다"는 뜻이다. 바꿀 때는 이 의미를 유지할지 결정 기록에 적는다.

## 6. 공개 저장소
- `private-docs/` 내용을 브랜드 문서에 옮기지 않는다. D-번호는 참조만 한다.
