## 변경 파일과 정답 계산

- `backend/src/orbit/evaldata/v1/task_world.py`: 세계·뼈대 일관성, 현지 날짜·일정 조회.
- `task_gold.py`: 유형별 질문·정답·최종 상태 계산. 일정은 세계에서 재조회하고 truth와 비교한다.
  메일·문서는 본문에 사실이 있는지 검사하며, 기권은 대상 부재를 재검사한다.
  모호성은 서로 다른 해석 답을 보존하고, 리마인더는 사용자 시간대로 계산한다.
- `task_templates.py`: 유형별 문구·상대 날짜와 현지 시각 표기.
- `tasks.py`: 균형 선택, 정답 지문 정규화, 근거 연결 요소 분할, 장애·표현 변형 파생, 스모크, CLI.
  모든 시나리오 근거와 정답 재계산에 사용한 근거를 합쳐 추적한다.
- `paraphrase.py`: 문장 검증·최대 3회 시도·교체·재개·비용 추정.
  누적 상한과 유한한 양수 검증을 추가했으며, 캐시를 다시 검증하고 모델 설정 혼합을 거부한다.
- `evaldata/schema.py`, `dataset.py`: v0 호환 선택 필드, 문서 근거, 과제만 쓰기, 스모크 목록 검증.
- `evalrunner/cli.py`: `--subset smoke`만 추가했다. 채점 구현은 그대로다.
- 테스트: `tests/eval_tasks_support.py`, `tests/unit/evaldata/v1/test_{tasks_gold,tasks_templates,tasks_suite,paraphrase}.py`,
  `tests/unit/evalrunner/test_tasks_v1_assistant.py`, `tests/integration/test_eval_tasks_v1_runflow.py`.
- 사용법: `eval/worlds/README.md`. 인계 명세: `docs/handoff/eval-v1-d2-spec.md`.
- 산출물: `eval/datasets/orbit-eval/v1/tasks.jsonl`, `manifest.json`. `review.jsonl`은 만들지 않았다.

## 표현 변형 비용 (`--dry-run`)

실행 명령은 `eval/worlds/README.md`에 있다. 24문항을 확보하기 위한 교체 후보 32개에
재시도 계수 1.3을 적용했다. OpenAI 직접 경로에는 요청당 추론 출력 300토큰을 추가 가정했다.

| 계열 | 모델·경로 | 후보 | 입력 토큰 | 출력 토큰 | 예상 USD |
| --- | --- | ---: | ---: | ---: | ---: |
| OpenAI | gpt-6-luna, 직접 | 11 | 8,566 | 5,359 | 0.0035 |
| Anthropic | claude-haiku-5.5, OpenRouter | 11 | 8,638 | 1,123 | 0.0014 |
| Google | gemini-2.5-flash-lite, OpenRouter | 10 | 7,737 | 912 | 0.0011 |
| 합계 | | 32 | 24,941 | 7,394 | 약 0.0061 |

단가는 `realize_models.py`의 **예시 기본값**이며 공급자 최신 견적을 조회한 값이 아니다.
실제 실행 전 사람이 단가·사용 가능 모델·프로젝트 잔여 예산을 확인하고 별도 승인해야 한다.
실행 시 상한은 저장된 시도의 비용까지 포함한다. 진행 중인 동시 호출 비용은 상한을 초과할 수 있다.

## 명세와 다른 부분·사람 검수

1. `--skip-paraphrase` 요청대로 변형 24문항을 제외해 216문항이다.
   7:12 test 비중을 유지하므로 90/126이며, 목표 100/140은 변형 포함 240문항일 때다.
2. 제품에는 초안 저장 전용 도구가 없어 답장·다중 턴 메일 과제는 승인 후 발송과 `draft_sent`를 쓴다.
   질문도 발송 요청으로 맞췄다. 초안만 저장하는 기능·평가는 별도 제품 작업이 필요하다.
3. 정답 지문 중복 제거는 원본에 적용한다. 장애·표현 변형은 같은 정답을 의도한 파생이라 유지한다.
   기권은 질문 대상, 승인 거절은 원래 계획한 변화를 지문에 포함해 서로 다른 과제를 구분한다.
4. 임시 실행 경로는 Linux의 `/tmp`를 사용했다. 실제 커밋 산출물은 지정된 데이터셋 폴더에 있다.
5. `assistant_v0`는 문서·쓰기·리마인더 생성 등 미지원 유형에서 실패가 정상이다.
   스크립트 LLM 검사는 생성 답과 채점의 연결만 검증하며 실제 모델 품질 측정이 아니다.

검수 우선순위:

- 질문만 보고 답 종류가 하나로 정해지는가? 모호성의 두 해석이 모두 자연스러운가?
- 최신 메일 하나를 고르는 정답이 타당한가? 같은 값을 반복한 다른 메일과 혼동하지 않는가?
- 이전 값 금지어 때문에 정정 설명까지 실패할 수 있다는 채점 한계가 허용 가능한가?
- 현지 날짜·종일 일정·LA 시간대와 상대 날짜, 리마인더 시각·비요청 의도가 맞는가?
- 기권 대상이 실제로 없고, 쓰기·거절·장애의 최종 상태와 승인 의도가 맞는가?
- 표현 변형 실제 생성 후에는 코드의 핵심 표현 검사 외에 의미 보존을 사람이 확인해야 한다.
- 검수·test 봉인은 아직 하지 않았다. 이후 검색 세트는 이 묶음·분할과 근거를 공유하면 같은 분할을 써야 한다.
