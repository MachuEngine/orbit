# 평가 결과 v1 — dev 비교와 test 확인

기록일: 2026-11-17. 종단 설정의 dev 비교와 완료된 test 확인 결과를 함께 다룬다. 기존 결과는 모델 호출 없이 집계했고, 후속 추가 측정의 조건·지출은 별도로 구분한다.

## 데이터셋과 채점

- 종단 과제 v1은 생성 시 240개다. 사람 검수에서 22개를 제외해 유효 과제는 **dev 88개 + 봉인 test 130개 = 218개**다. test는 독립 묶음 102개, dev는 73개다. 매니페스트의 생성 전 분할 수와 봉인·검수 후 수를 구분한다(ADR-0026).
- dev 비교는 같은 88과제 × 3회 = 설정당 264에피소드다. 다중 턴은 dev 9대화(27에피소드)이며 기존 데이터에는 중간 턴별 정답이 없다. 스모크 목록은 생성 시 25개, 검수 제외 후 21개다.
- 검색 질의는 생성 180개에서 검수 제외 47개를 뺀 **133개(dev 55, test 78)**다. 메일만 색인하므로 문서 정답 질의를 더 빼면 메일 검색 평가는 dev 37개·13묶음, test 51개·19묶음이다(ADR-0028).
- 성공은 구조화된 답, 최종 상태, 궤적·승인 규칙으로 판정한다. 과제의 반복 평균을 구하고 근거를 공유하는 cluster 단위 bootstrap 95% CI를 낸다. 짝 차이는 같은 과제·반복을 맞춘 A−B다. 반복 264개를 독립 표본으로 취급하지 않는다(ADR-0010).

### 평가셋 구축에 쓴 LLM

정답과 근거 태그는 코드가 구조에서 계산했고, LLM은 문장 생성과 검수 보조에만 썼다(ADR-0026 §2·§8). 세 계열은 `openai/gpt-6-luna`(추론 강도 low, OpenAI 직접), `anthropic/claude-haiku-5.5`, `google/gemini-2.5-flash-lite`(둘 다 OpenRouter)다.

| 단계 | 역할 | 규모 | 프롬프트 | 기록 비용(USD) |
| --- | --- | --- | --- | --- |
| 본문 실현 | 메일·문서 본문을 세 계열이 시드로 나눠 작성. 필수·금지 사실, 개인정보 형식은 코드로 검사하고 실패하면 재생성 | 본문 7,022개(계열별 약 2,340개), 템플릿 대체 14개 | `realize-v1`, 실존 상표 재검사 29개는 `realize-v2` | $1.746627 |
| 표현 변형 | 과제 질문을 다른 표현으로 바꾼 파생 문항 생성 | 24문항 사용(후보 25개 시도) | `paraphrase-v1` | $0.002646 |
| 자동 검수 (LLM Judge) | 과제·검색 질의마다 생성 계열을 뺀 두 계열이 자연스러움·정답 타당성·답 유일성을 판정해 사람 검수 대상을 표시 | 372항목(과제 192, 검색 180), 1,198회 호출, 표시 54항목(과제 29, 검색 25), 파싱 실패 0 | `review-v1` | $0.332821 |

- 자동 검수 결과는 판정을 확정하지 않는다. 표시된 항목 전부와 나머지에서 무작위 10%를 사람이 검수했고, 최종 제외 22과제·47검색 질의는 사람 판정이다. 표현 변형 23문항도 사람이 확인했고 문제는 0건이었다.
- 자동 검수에서 반복된 결함(질문의 사실 이름, 검색 질의의 날짜 이름, 본문의 다른 연도, 일정 생성 정답의 지어낸 종료 시각·참석자)은 사람 검수 전에 생성기를 고쳐 해결했다.
- 자동 검수 Judge와 사람 검수의 일치도는 재지 않았다. 사람이 자동 검수 지적을 보며 판정했으므로 둘은 독립된 판정이 아니다(기준점 효과).
- 본문 실현과 자동 검수의 단가는 실행 당시 기본값으로 기록됐다. 매니페스트에 "실행 전에 공급자 가격표로 확인해야 한다"라고 남아 있으므로 위 비용은 청구액이 아니라 기록된 사용량 × 설정 단가다.
- 본문을 쓴 계열이 평가 대상 모델과 같으면 자기 계열 본문에서 유리할 수 있다. 계열별로 나눈 성능 비교는 아직 하지 않았다.

출처: `eval/datasets/orbit-eval/v1/realize-manifest.json`, `auto-review-manifest.json`, `auto-review.jsonl`, `manifest.json`의 `details.paraphrase`·`seal.review`.

## dev 설정 비교

이 표의 비교 기준은 당시 측정한 **runflow_v0 · react · luna · 색인 끔(0.49)**이다. 이후 채택한 ADR-0031 기준은 **luna · react · 색인 켬(0.64)**이다. 아래 차이를 색인 켬 대비 차이로 읽으면 안 된다. haiku·gemini는 각각 `anthropic/claude-haiku-5.5`, `google/gemini-3.5-flash-lite`다. luna는 `openai/gpt-6-luna`, 추론 강도 `none`이며 실제 제공자 요청은 온도를 보내지 않았다. OpenRouter 모델의 추론 강도는 설정되지 않았다. 실사용 `low`와 같은 조건이 아니다.

plan의 비용은 비용을 알 수 있는 253에피소드의 합이다(11개 비용 미상). 성공 1건당 비용 역시 비용을 아는 성공 99건만 분모에 넣는다. 다른 설정은 264건 모두 비용을 기록했다. 비용 미상 11건을 LLM 오류 11건으로 해석하지 않는다.

## 추론 강도 low 비교(dev)

ADR-0031 기준인 `runflow_v0 · react · luna · 메일 색인 켬`에서 추론 강도를 `low`로 측정했다. dev 88과제 × 3회, 시드 0, 독립 묶음 73개다. 비교 대상은 기존 `compare-v1/index-on.jsonl`의 `none`이며 짝 누락은 없다. 모델·단가(입력/캐시/출력 1M 토큰당 $0.10/$0.01/$0.50)·도구·색인 지문·에피소드 예산(50단계·200,000토큰·120초)은 같다.

| 추론 강도 | 성공률 [95% CI] | low − none [95% CI] | pass^3 | LLM 비용 / 성공 1건당(USD) | 지연 p50 / p95(ms) |
| --- | --- | --- | --- | --- | --- |
| none | 0.644 [0.544, 0.736] | — | 0.500 | $0.198304 / $0.001166 | 6267 / 13975 |
| low | 0.602 [0.504, 0.696] | -0.042 [-0.109, +0.020] | 0.455 | $0.197937 / $0.001245 | 6606 / 14815 |

low의 점추정은 none보다 4.17%p 낮지만 CI가 0을 포함한다. 이 표로 low의 열세나 동등성을 확정하지 않는다. **low가 정확도를 높였다는 증거는 확인하지 못했다.** 실험 기준 none과 실사용 설정의 변경 여부는 사용자 결정으로 남기고 설정 파일·서버·워커를 바꾸지 않았다.

### 실행·비용과 비교 한계

- `--estimate 8` 결과: 전체 264에피소드 LLM 비용 약 $0.232105 추정. 사전 8건의 실제 기록 비용은 $0.00703349다.
- 본 실행은 `--max-cost-usd 0.6`으로 **264/264 완료**, LLM 비용 $0.19793660, 비용 미상 0건, 모델 불일치 0건이다. 사전 측정 포함 기록된 LLM 지출은 **$0.20497009**다. 사전 8건은 성공률·CI 집계에서 제외했다.
- 임베딩은 사전·본 실행 각각 `--max-embed-cost-usd 0.01`을 걸고 같은 `runs/embed-cache`를 썼다. 색인 dry-run은 새 청크·임베딩 호출 0건이고 실제 색인도 전부 재사용했다. CLI가 본문 질의의 종료 시점 임베딩 누적 비용을 별도 저장하지 않아 위 LLM 합계에 임베딩 실측값을 더하지 않았다. 임베딩의 설정 상한과 LLM 기록 지출을 구분한다.
- 본 실행 기록의 전체 토큰은 4,437,799, 그중 추론 토큰은 4,434다. 추론 토큰은 출력 토큰에 포함되므로 중복 과금 계산하지 않았다.
- 코드 SHA는 low `c627a789ce94`, none `fda3bf3`이다. low는 승인·머지한 B 수정 이후 main에서 실행했다. B는 정상 react 요청·지문·지연 지표 의미를 보존했지만 코드 SHA와 시간 초과 경계의 구현 차이는 남는다.
- 현재 OpenAI 어댑터는 effort가 none이 아니면 추론 항목 되돌리기를 자동으로 켠다(`llm/config_info.py`). 따라서 low의 `reasoning_items_roundtrip=true`는 기존 코드의 파생 동작이며, 되돌리기를 끈 순수 추론 강도 ablation은 아니다.
- 단가는 같지만 가격 출처 메타데이터 표기는 이전 실행과 다르다. 누적 토큰 상한은 none에 12,000,000, low에는 없고 비용 상한 $0.60을 사용했다. 두 실행 모두 끝까지 완료했고 low의 토큰 합계는 12,000,000 미만이지만, 설정 지문이 effort 항목 하나만 달라진 실험이라고 표기하지 않는다. 실행 시점·캐시 상태도 같지 않아 비용·지연은 관찰값으로 해석한다.

출처: `compare-v1/index-on-low.jsonl`, `followup-20261117/low.stats.json`, `low.vs-index-none.json`, `estimate-low.log`, `run-low.status.json`. low 결과 설정 지문은 `f886d6ed7c7b5ca349ba4709fbfab28d12942f35e824230616aa690398eb2c6e`, 원본 SHA-256은 `a774a42d28fefcee786a1dd86a6016060cf872fe44e290cf900393f627fb1126`다. 정지 감시 조건(10분 무진행)은 발동하지 않았다. low의 test 확인은 실행하지 않았다.

`gmail_search`는 실제 Gmail 서비스가 아니라 Sim 커넥터의 검색 문법에 질의 문장 전체를 넣은 기준선이다. keyword는 Kiwi + `ts_rank`로 BM25와 다르다. BM25는 같은 토큰으로 별도 계산했다. 5,000통에서 vector와 hybrid의 R@10 차이는 +0.020 [−0.085, +0.118]로 구분되지 않는다(파일의 `paired_a_minus_b.5000.vector-hybrid.recall@10`). test에서 가장 높은 점추정을 보고 새 설정을 고르면 test 선택 편향이 생기므로 이 표만으로 방식을 다시 선정하지 않는다.

## Judge 근거성 비교

기준선 두 경로(assistant·runflow) 528에피소드에 사후 적용한 기존 `judge/agreement-ab.json`의 에피소드 grounded 이진 판정을 읽었다. A는 haiku 계열, B는 gemini-2.5-flash-lite 계열이다. B의 판정 없는 16개를 제외한 **512개·73묶음**에서 일치율 0.645, **Cohen's kappa 0.10 [0.003, 0.203]**다. 기준 0.6에 미달한다. A의 grounded는 341/528, B는 431/512다. 서로 주장을 나누는 방식이 달라 주장 단위 일치도로 바꾸어 해석하지 않는다.

이 값은 **Judge끼리의 일치도**이며 사람과의 일치도가 아니다. Judge 근거성 점수는 모델·설정 선정의 확정 지표로 사용하지 않는다.

### v2 세트: 표면 치환 (프롬프트 judge-v2)

계산·단위 환산·시각 이동과 빈 시간 계산, 빈 조회의 부재 보고, 비서가 직접 작성한 제안, 성공한 쓰기 결과의 완료 보고를 허용하는 기준을 프롬프트에 명시했다. 반대로 도구와 다른 값·없는 사실·실패하거나 실행하지 않은 행동의 완료 보고는 근거 없음이다. 응답 형식과 실사용 프롬프트는 그대로다.

정정한 원본 60건에서 실제 사실 주장이 있고 근거를 확인한 변조 후보 38건을 검토했다. 시드 `20261117`로 그중 30건을 골라 답의 사실 하나를 바꾸고, 새 값이 도구 결과에 없음을 확인했다. 변조는 날짜 14건·시각 1건·이름 7건·장소 4건·금액 4건이다. 나머지 원본 30건과 섞은 60건에서 각 원본 에피소드는 한 번만 사용했다. 원본의 독립 근거 묶음은 38개다. 후보 선정은 제안이나 부정 표현을 잘못 음성으로 만드는 일을 피하기 위한 것으로, 모든 환각 유형을 대표하는 표본은 아니다. 프롬프트 보정에 사용한 원본 60건을 재사용했으므로 독립 검증 세트도 아니다. 사람 라벨 기준을 통과해도 일반적인 환각 탐지 성능으로 확대 해석하지 않는다.

익명 입력·라벨링 HTML에는 정답 키, 원래 에피소드 ID, 변조 표시, Judge 예측을 넣지 않는다. 근거 후보는 답과 표현이 겹치는 도구 결과 줄이며 자동 정답 표시가 아니다. 금액 단위를 정규화하고 전체 도구 결과도 펼쳐 볼 수 있다. 원문·정답 키·개별 판정은 git 제외 경로에만 둔다.

다음 표는 정답 키에 대한 점추정이다. 재현율은 변조본의 근거 없음 판정/30, 오경보율은 원본의 근거 없음 판정/30, 정확도는 키와 일치한 판정/60이다. 판정 누락은 별도로 보고하며 정확도나 재현율의 분모에서 빼지 않는다. 도구 결과 본문의 최대 길이는 7,885자로 모든 입력이 Judge의 합계 12,000자 상한 안에 들어갔다. Google 계열 두 모델은 별도 출력 폴더를 썼다.

사람 라벨 뒤에는 익명 번호를 원본과 연결하는 비공개 키로 각 모델과 사람의 kappa를 계산한다. 신뢰구간을 계산할 때는 익명 문항 ID를 독립 묶음으로 간주하지 않고 원본 입력의 38개 `cluster_id`를 복원해 bootstrap한다.

집계 근거는 `judge/blind60-summary.json`, 각 `judge/v2-blind60-{flash36,haiku55,lite25}/metrics-key.json`과 `judge.jsonl`이다. 입력·생성 감사 기록은 `judge/blind60-manifest.json`, `judge/blind60-audit.json`에 있다. 사람용 자료는 `judge/blind60.html`과 같은 문항의 `judge/blind60.txt`다. 라벨은 `1t,2f,...` 형식으로 받으며, 60개 번호의 중복·누락을 검사해 익명 ID에 매핑한 뒤 kappa와 통과 여부를 갱신한다.

v2의 변조 30건은 모두 도구 결과에 없는 값으로 바꿨다. 문자열 대조로 잡을 수 있는 변형이므로 이 결과만으로 Judge 고유 가치를 측정하지 못한다. v2 입력·키·결과는 그대로 보존하고 다음 v3 세트를 별도로 비교한다.

### v3 세트: 관계·시점·상태 변형 (같은 프롬프트 judge-v2)

시드 `20261118`로 원본 30건·변형 30건을 새로 배치했다. 같은 에피소드가 양쪽에 들어가지 않으며, NFKC·공백·구두점·Markdown을 정리한 답의 해시도 60개가 모두 다르다. v2에서 같은 답이 나온 반복 항목도 이 검사로 걸렀다. 고정 치환과 문형 목록을 로컬 Python으로 적용했으며 문장 생성·교정용 LLM 호출은 하지 않았다.

| 유형 | 목표 | 실제 | 바꾸는 관계 |

원래 답의 사실과 정정 전 값이 도구 결과에 함께 확인되는 stale_value 후보는 3건이었다. 그중 기한 2건은 같은 과제의 다른 반복이고 결정 1건은 별도 과제다. 옛 메일의 날짜나 핸들만 바꾸는 것으로 수를 채우지 않고, 부족한 2건을 role_swap과 unsupported_addition으로 한 건씩 보충했다. 따라서 30건 중 **24건이 surface 외 유형**이다.

stale_value와 role_swap은 새로 들어간 날짜·시각·금액·이름·장소를 자동 추출하고, 검토 manifest에 선언한 값과 함께 도구 결과에서 존재를 검사했다. 선언에서 값을 누락해도 자동 검사를 우회하지 못하게 테스트한다. 다만 글자 추출 자체의 누락 가능성은 남으므로 원본·변형·근거의 의미 대응은 별도로 검토했다. 유형·변경 설명·원래 ID는 비공개 키에만 두고 라벨링 HTML에는 넣지 않았다. 근거 후보 표시 방식과 판정 프롬프트는 v2와 같다.

문자열 대조 기준선은 기존 `evalrunner/fact_extract.py`의 날짜·시각·금액·호칭 이름 추출을 재사용하고, 명시적인 이름표와 장소 표현을 보완했다(`fact-extract+strict-label-place-v1`). 일반 숫자·이메일은 이번 기준선의 검사 대상에서 제외했다. 답의 추출 값 중 도구 결과에 없는 것이 하나라도 있으면 근거 없음, 추출 값이 없으면 근거 있음으로 판정한다. 키·변형 유형·manifest는 기준선의 입력으로 쓰지 않는다. 집계는 `judge/v3-blind60-set/blind60-summary.json`의 `baseline`, `models`, `baseline_counterfactual_audit`와 각 `judge/v3-blind60-{flash36,haiku55,lite25}/metrics-key.json`을 사용했다. 입력·키·HTML·텍스트와 구성 부족·보충 기록은 `judge/v3-blind60-set/`에 있다.

#### v3 사람 라벨 대조와 Judge 결정

2026-11-17에 개발자 1명이 v3 라벨링 HTML 60건에 라벨을 붙였다. 정답 키·변형 유형·Judge 판정은 보지 않았다. kappa는 `evalrunner/judge.py`의 `cohen_kappa`, 신뢰구간은 원본 과제의 `cluster_id` 38개를 복원한 `bootstrap_kappa_ci`(10,000회·seed 0)로 계산했다. 이 계산에 유료 호출은 없다.

| 모델 | 사람과 일치율 | 사람 kappa [95% CI] | 판정 수 |
| --- | --- | --- | --- |
| gemini-3.6-flash | 0.817 | **0.636** [0.446, 0.805] | 60 |
| claude-haiku-5.5 | 0.783 | 0.575 [0.395, 0.750] | 60 |
| gemini-2.5-flash-lite | 0.729 | 0.454 [0.247, 0.641] | 59 |

- 사람 라벨은 정답 키 기준 변형 30건 중 22건을 근거 없음으로 판정했다. 놓친 8건은 role_swap 4, unsupported_addition 3, surface 1건이다. 같은 8건을 Flash·Haiku는 모두 근거 없음으로 판정했다. 따라서 위 kappa는 Judge의 오류만이 아니라 사람 라벨의 놓침도 반영한 값이다.
- 원본 30건 중 사람은 5건을 근거 없음으로 판정했다. 사람이 근거 있음으로 본 원본 25건에서 Flash는 0건, Haiku는 3건, Lite는 2건을 근거 없음으로 판정했다. 사람이 근거 없음으로 본 원본 5건 중 Flash는 2건만 같은 판정을 냈다.
- 라벨링 중 정한 판정 규칙: 빈 조회 뒤의 "찾지 못했다"와 미실행을 사실대로 말한 "보내지 못했다"는 근거 있음이다. 도구 결과에 없는데 "그 기능이 없다", "읽기 전용이다"처럼 기능 부재를 단정하면 근거 없음이다. 이 규칙은 현재 Judge 프롬프트 `judge-v2`에 없다. 원본 5건의 차이 일부가 이 규칙 차이일 수 있지만 문항별로 확인하지 않았다.

**결정: 근거성 Judge는 `google/gemini-3.6-flash`로 정한다.** 점추정 기준 사람 kappa ≥ 0.6과 근거 없음 재현율 ≥ 0.8(정답 키 기준 30/30)을 함께 충족한 유일한 모델이다. 다만 kappa 95% CI 하한이 0.446이라 0.6 이상이 통계적으로 확정된 것은 아니다. 라벨러가 1명이고 표본이 60건이다. 남은 근거성 채점에서 Judge 점수는 기존 성공률 비교를 바꾸는 확정 지표가 아니라 보조 지표로 보고한다. 기능 부재 단정 규칙은 다음 Judge 실행 전에 프롬프트 버전을 올려 반영하고, 그 전 결과와 버전을 구분한다.
