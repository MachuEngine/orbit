# 평가 스위트 v1 (e) 검색 세트

## 범위

PR #23이 main에 머지된 `98670b9`에서 `eval/v1-search-set` 브랜치를 만들었다.
먼저 ADR-0026 §4에 답장 과제가 초안 저장 대신 승인 후 발송(`draft_sent`)을 평가하는 이유를 명시했다.
이번 단계는 합성 검색 질의·관련도와 순수 지표 함수만 구현한다. 실제 검색·색인·임베딩 실행기는 포함하지 않는다.

실제 LLM 호출과 추가 LLM 비용은 **0**이다. `secrets/`·`private-docs/`는 읽지 않았다.
기존 세계·뼈대·종단 과제와 제품·채점 규칙·하네스는 유지했다.

## 생성 결과

검색 주제 60개에서 주제당 3개, 총 **180개**를 생성한다.

| 형태 | dev | test | 합계 |
| --- | ---: | ---: | ---: |
| 키워드 (`keyword`) | 25 | 35 | 60 |
| 자연어 질문 (`question`) | 25 | 35 | 60 |
| 사람·시점 (`person_time`) | 25 | 35 | 60 |
| 합계 | 75 | 105 | 180 |

- 독립 묶음: dev 25, test 35, 총 60개. 같은 주제의 세 질의는 한 묶음이다.
- 버린 질의: 0개. 주제 문구 충돌·정답 값 포함·정규화 중복이 실제 입력에는 없다.
- 등급 1 혼동 사례가 없는 주제: 0개.
- 기존 d2 과제와 공유하는 근거 body: 0개.

관련도 표는 주제 60개를 한 번씩 센 값이다. 같은 주제의 질의 세 개는 같은 관련도 맵을 공유한다.

| 메일함 크기 | 등급 0 | 등급 1 | 등급 2 |
| --- | ---: | ---: | ---: |
| 200 | 36 | 60 | 60 |
| 1,000 | 96 | 60 | 60 |
| 5,000 | 156 | 60 | 60 |

세 메일함 모두 문서 24개를 포함한다. 크기 표시는 메일 수이며, 파일 ID와 메시지 ID는 계정마다 다르다.
작은 메일함이 큰 메일함의 부분집합인지 공통 `body_id`로 검증한다.

실제 생성된 질의 예시:

| 형태 | 질의 |
| --- | --- |
| 키워드 | 달빛정원 시연 일정 최신 최종 금액 자료 |
| 자연어 질문 | 달빛정원 시연 일정의 최종 금액이 확인되는 최신 자료를 찾아줘 |
| 사람·시점 | 2026년 10월 무렵 전준혁님이 다룬 달빛정원 시연 일정 최종 금액 자료가 필요해 |

## 변경 파일

- `backend/src/orbit/evaldata/v1/search_set.py`: 생성·관련도 변환·검증·묶음 분할·매니페스트·CLI·저장 파일 로더.
- `backend/src/orbit/evaldata/v1/search_templates.py`: 정답 값을 사용하지 않는 세 형태의 한국어 질의.
- `backend/src/orbit/evalrunner/retrieval_metrics.py`: recall@k, MRR, 선형 gain nDCG 순수 함수. 기존 채점 코드와 연결하지 않았다.
- `backend/tests/unit/evaldata/v1/test_search_set.py`, `backend/tests/unit/evalrunner/test_retrieval_metrics.py`: 관련도·불변식·결정성·실패 조건·지표 검사.
- `docs/adr/ADR-0026-eval-suite-v1.md`: §4 답장 과제 정정과 §6 검색 세트 구체화.
- `eval/worlds/README.md`: 생성 명령, 출력·지표·제약 설명.
- `eval/datasets/orbit-eval/v1/search.jsonl`, `search-manifest.json`: 실제 생성 결과. 생성기 SHA와 입력 해시는 매니페스트에 기록한다.

## 검증 정책과 한계

- 등급은 truth에서 그대로 가져온다. 각 계정의 매핑이 뼈대의 ID·body 대응 및 실제 세계의 ID와 맞는지 검사한다.
- 등급 1·2는 200통 메일함에도 있어야 하며, 모든 계정의 등급 2 본문에서 fact 표기를 확인한다.
- 등급 0은 해당 메일함에 실제로 존재하는 것만 기록한다. 작은 메일함에 없는 등급 0 후보는 생략한다.
- 정규화는 NFC·대소문자·공백 차이를 제거한다. 정답 표기 포함, 전체 주제 문구의 겹침, 중복 질의를 탐지한다.
  프로젝트 이름 같은 개별 단어의 공유만으로 주제가 충돌한다고 보지는 않는다.
  필터 후 질의가 2개 미만 남는 주제는 남은 질의도 버려, 포함한 주제마다 2~4개 조건을 지킨다.
- 사람·시점 질의는 실제 발신자 또는 문서 소유자, 계정 현지 시각의 발송·수정 월을 사용한다.
  문서 소유자가 작성·수정했다는 근거 없는 주장은 하지 않는다.
- 같은 주제 또는 공유 body를 연결 요소로 묶고, d2와 같은 7/12 test 비중(약 4:6)을 목표로 분할한다.
  test 질의 수의 허용 오차는 `max(3개, 전체의 5%)`다. 두 분할이 비어 있지 않고 이 오차를 만족해야 한다.
  만족하지 못하면 실패하며, 종단 과제의 test 최소 100묶음 조건은 적용하지 않는다.
- 검색 결과의 중복 ID는 첫 등장만 남긴 뒤 k와 순위를 적용한다. 관련 항목이 없는 경우 지표는 0이다.
  recall은 등급 2와 등급 1 이상을 별도로 계산하고, MRR은 첫 등급 2의 역순위다.
  nDCG는 등급 자체를 gain으로 쓰며 지수 gain은 사용하지 않는다.
- test 질의는 105개여도 독립 묶음은 35개다. 변형 세 개를 독립 표본으로 보면 정밀도를 과대평가한다.
  독립 묶음 35개에 최악 분산을 가정한 정규 근사의 95% 비율 반폭은 약 ±16.6%p다.
  이는 실제 측정 신뢰구간이 아니라 규모의 한계를 설명하는 예시이며, 실제 비교는 묶음 단위 통계가 필요하다.

## 명세와 다른 부분·사람 검수

범위를 바꾸지 않았다. 명세가 정하지 않은 중복 순위 처리·빈 관련도 점수·분할 허용 오차는 코드와 문서에 명시했다.
등급 1이 없는 입력은 단언 위반으로 생성에 실패하고 누락 주제 수를 오류에 표시한다. 유효 출력의 매니페스트에도 그 수를 기록한다.

사람 검수에서는 다음을 우선 확인한다.

- 세 문구가 같은 주제를 찾으며, 최신 금액·마감 의도와 관련도 정답표가 맞는가? 표현의 매끈함보다 이 일치 여부를 우선한다.
- 이전 값의 등급 1과 최종 근거의 등급 2가 질의 의도에 맞는가?
- 사람·월 단서가 실제 근거에 맞고 정답 날짜나 금액을 노출하지 않는가?
- 등급 0 후보가 정말 답과 무관한 어려운 오답인가?
- 메일함 세 크기에서 질의와 관련도 의미가 같고, 부가 메일만 늘어나는가?
- 반복 변형의 상관과 test 35묶음의 정밀도 한계를 비교 실험에서 반영하는가?

사람 검수·test 봉인은 다음 단계이며 이번에는 수행하지 않았다. 공개 저장소의 정답은 읽을 수 있으므로
향후 검색 실행기도 test 실행 시 명시적 확인을 요구해야 한다. 색인 저장·재사용 방식은 RAG 실험 전에 따로 정한다.
