# ADR-0035 — 메일 RAG 검색 시점과 질의 재작성의 종단 비교

- 상태: 실험 중 (2026-11-19 개발자 지시: "rag패턴 비교 평가 진행해줘")
- 작성일: 2026-11-19
- 후속: 이 ADR은 검색 정책 비교다. RAG 아키텍처 비교(Naive·Advanced·Agentic·Adaptive·GraphRAG)는 ADR-0036에서 한다. 문서 표기만 바꾸고 코드 식별자는 유지한다.
- 근거: ADR-0010(짝 비교·봉인), ADR-0019(메일 색인), ADR-0023(실사용 그래프 평가), ADR-0028(색인 재사용), ADR-0029(기록·지표), ADR-0031(기준 설정), ADR-0034(시간 상한), 평가 계획 §2·§4-4

## 문제

기존 평가는 색인 ON/OFF의 종단 효과와 검색 알고리즘 단독 성능을 측정했다. 현재 도구 호출형 Hybrid RAG와 다른 검색 시점·질의 생성 정책을 같은 생성 모델·에이전트 패턴에서 종단 비교한 기록은 없다. 검색 설정을 바꿨다고 해서 생성 모델·승인·채점도 함께 바꾸지 않는다.

## 비교할 구성

| 설정 | 생성 모델 | 추론 강도 | 에이전트 패턴 | 검색 정책 |
| --- | --- | --- | --- | --- |
| R0 기준 `agentic` | `openai/gpt-6-luna` | `none` | ReAct | 현재 도구 호출형 RAG. 모델이 색인 검색 시점·질의·호출 수를 선택 |
| R1 `retrieve_once` | 동일 | 동일 | 동일 | 사용자 턴 시작에 질문 원문으로 Hybrid 검색 1회. 이후 그 턴의 추가 색인 검색은 비활성 |
| R2 `rewrite_retrieve_once` | 동일 | 동일 | 동일 | 사용자 턴 시작에 같은 모델로 검색 질의를 1회 재작성한 뒤 Hybrid 검색 1회. 이후 추가 색인 검색은 비활성 |

- R1·R2는 전체 앱을 단일 텍스트 생성 체인으로 바꾸는 Naive RAG 구현이 아니다. **색인 검색을 턴당 1회로 제한한 Retrieve-then-Act 근사**다. 메일 읽기, 기존 제공자 문법 검색, 일정·문서 조회, 승인·쓰기·리마인더와 구조화된 답 제출은 ReAct 흐름을 유지한다.
- R0→R1은 검색 시점·질의·반복 정책을 함께 바꾸는 패턴 비교다. 단일 요인 효과로 주장하지 않는다. R1→R2는 같은 검색 시점·1회 정책에서 질의 재작성의 추가 효과를 본다.
- 검색은 운영과 같은 Hybrid(Vector + Kiwi/`ts_rank`, RRF k=60), 후보 각 50개, 메일 단위 대표 청크를 사용한다. R1·R2는 top-5로 고정하고 R0는 기존 모델의 결과 수 선택(기본 5·최대 20)을 유지한다. 임베딩 `text-embedding-3-small`, 800자 청크·100자 겹침과 고정 색인·캐시를 유지한다. 새 reranker·임베딩·청크 비교는 이번 범위에 넣지 않는다.

## 구현 경계와 보존 조건

1. 평가 CLI의 명시적 `--rag-pattern`으로만 켠다. 기본 `agentic`에서는 기존 요청·도구·프롬프트·SUT 버전·runflow 지문이 변하지 않는다. 기본 CLI 출력 설정에 불필요한 새 키도 넣지 않는다.
2. 변형은 `runflow_v0`, `--index on`, ReAct에만 허용한다. 부적합 조합은 출력·DB·API 호출 전에 거부한다. 제품 워커·API에 변형을 켜는 경로는 추가하지 않는다.
3. 초기 검색은 서버가 만든 호출임을 표시하고 기존 읽기 도구 실행·작업 집합·RLS·데이터 봉투 경로를 거친다. transcript의 예약 step `-1`로 구분하되 그래프 상태에 음수 step은 넣지 않고 실제 ReAct step은 기존 0부터 시작한다. 모델 호출·토큰·비용을 합성하지 않는다. 합성 호출은 실제 LLM 응답과 구분하고 trace에 초기 검색과 질의 재작성 단계를 남긴다.
4. 재작성은 현재 사용자 발화와 그 시점까지의 과거 대화만 사용한다. episode의 미래 발화, gold, 참조 태그, task 유형·split을 모델에게 넘기지 않는다. 별도 버전 상수의 프롬프트, 최대 500자 질의, 제한된 출력 토큰, 한 번 호출 규칙을 둔다. 빈 값·형식 오류는 원 질문으로 되돌아가고 그 횟수를 기록한다. LLM 전송 오류·예산 초과는 정상 실패로 남기며 숨기지 않는다.
5. 초기 검색 결과와 핸들은 RLS가 적용되는 기존 transcript에만 저장한다. 그래프 상태·작업 인자·로그에 원문·주소·프롬프트를 추가하지 않는다. 재실행 때 같은 턴 초기 검색을 중복 호출하지 않는다.
6. R1·R2의 추가 색인 검색 제한은 모델에 보이는 도구 목록뿐 아니라 실행 코드에서도 강제한다. 기존 쓰기 승인·인자 해시·실행 선기록·Connector 경계는 그대로 둔다.
7. 질의 재작성의 호출·토큰·재시도·비용은 기존 `Episode.llm`과 러너 예산으로 센다. 임베딩은 별도 누적 상한·최종 통계로 기록한다. 준비·실행·관찰은 ADR-0034의 episode 상한 안에 두고, 정리는 기존 별도 5초 유예를 유지한다.

## 과제와 통계 사전 규칙

- **주 비교**: 검수 후 dev 중 `scenario:mail_fact` 태그인 21 tasks·17 clusters. 단일 턴 16개와 다중 턴 5개를 포함한다. 각 설정 3회 반복, seed 0 → 63 episodes. 태그는 러너의 부분집합 선정에만 사용하고 SUT 입력에는 노출하지 않는다.
- **스모크**: 봉인된 manifest 목록 중 유효 dev 21 tasks·21 clusters, 각 설정 1회. 기능 퇴행 관찰용이며 주 비교의 성공 수·CI와 합치지 않는다. 주 비교와 겹치는 과제를 독립 표본으로 더하지 않는다.
- test 과제·독립 검색 test는 실행하지 않으며 봉인된 데이터셋 파일은 수정하지 않는다. 기존 88개 dev 전체나 130개 test의 점수와 이번 메일 부분집합 점수를 직접 순위 비교하지 않는다.
- R0도 새 코드에서 다시 측정한다. 기존 64.4% dev·64.6% test 기준선을 재사용해 이번 부분집합 차이를 계산하지 않는다.
- 주 지표: task success, R1−R0·R2−R0·R2−R1의 같은 task/repeat paired difference, cluster bootstrap 95% CI(10,000회·seed 0), pass³.
- 보조: 실패 유형, 코드 사실 근거율·인용, 다중 턴 성공, 검색 호출·0건 반환·재작성 fallback, 도구 호출, 실제 LLM/임베딩 비용, episode latency p50·p95. 기존 코드 지표의 추출·문자열 한계를 명시한다. Grounding Judge 추가 호출은 하지 않는다.
- 기존 독립 검색 dev 결과는 Hybrid 고정 설정의 배경 정보로 연결한다. 이번 RAG 제어 정책의 성능을 기존 고정 질의 Recall@10과 같은 지표로 취급하지 않는다. 별도 검색 정책·oracle-context 비교가 없어 원인별 기여율은 주장하지 않는다.
- 우열은 전체 메일 부분집합의 paired CI로 판단하며 작은 유형별 수치는 진단용이다. 다중 비교 보정·운영 일반화는 검증하지 않는다. 양의 점추정과 CI가 0을 넘어도 기준 설정 변경은 개발자 결정으로 남긴다.

## 비용과 실행 순서

- 이번 작업의 전체 LLM+임베딩 기록 지출 상한은 **$1**이다. 한 번에 runflow 하나만 실행한다. 실행 전에 다른 평가 프로세스를 확인하고, 배타 잠금과 10분 무진행 시 자기 프로세스 그룹만 종료하는 감시를 둔다.
- 원본·로그·통계는 git 제외의 새 `runs/rag-patterns-v1/`에 보존한다. 기존 `test-v1/`, 중단 파일, 다른 평가 worktree의 결과는 덮어쓰지 않는다. 키는 스크립트에서 기존 `secrets/.env`를 source해서만 사용한다.
- 유료 호출 전 비용 0의 색인 dry-run과 코드·테스트·검토를 완료한다. 각 설정의 `--estimate 8`을 먼저 실행하고 사용 비용까지 누적한다. 과거 runflow 약 $0.0007/episode를 단순 적용하면 주 비교 189 episodes 약 $0.13, 스모크 63 episodes 약 $0.04이며, 추가 문맥·재작성·다중 턴·재시도로 늘 수 있다. 실측 estimate를 우선한다.
- 총 estimate와 이미 쓴 금액이 상한을 넘거나 비용 미상 호출이 발생하면 본 실행을 시작하지 않고 보고한다. 본 실행마다 남은 누적 예산에서 LLM·임베딩 상한을 나눠 건다. 다음 설정은 이전 실행 비용을 확정한 뒤 진행한다.
- 단가·코드 SHA·설정/입력/색인 지문·각 실행의 추정/관측/미상 비용을 기록한다. 비용 미상을 $0으로 간주하지 않는다. 상한은 최종 제공자 청구액의 절대 보장이 아니라 기록 비용과 토큰 가드에 기반한 실행 통제다.

## 검증과 산출물

- ScriptedLLM: 변형별 초기 검색 순서·1회 제한·재작성/fallback·여러 턴·재실행 멱등, 데이터 봉투·핸들·권한, 오류·시간/단계 예산·비용 집계, 잘못된 CLI 조합, agentic 기본 지문·요청 보존.
- 기존 runflow·ReAct·승인·격리 회귀와 전체 `set -a; source backend/dev.env; set +a; scripts/check.sh` 통과. 테스트 삭제·완화로 실패를 숨기지 않는다.
- 구현·검토가 끝난 코드 커밋을 고정한 뒤 평가한다. 결과는 `docs/eval/rag-patterns-v1.md`에 생성 모델·에이전트 패턴·검색 정책·추론 강도를 분리해 적고, 집계 원본·비용·CI·한계를 연결한다.
- 공개 저장소 커밋 전 비밀정보·개인정보와 하네스 보호 목록을 검사한다. PR과 CI까지 완료하되 머지는 하지 않는다. 결과 HTML에도 실측 결과와 미실행을 구분해 반영한다.

같은 코드 `5a03946b96c1981debf651545c44341c240a3d61`에서 주 비교 63 episodes/설정과 스모크 21 episodes/설정을 완료했다. 메일 dev 성공률은 R0 76.2%, R1 74.6%, R2 81.0%다. R2−R0는 +4.8 pp [−3.3, +12.3], R2−R1은 +6.3 pp [−1.5, +15.8]로 두 차이 CI 모두 0을 포함한다. 개선·동등성을 확정하지 않고 기준 설정을 유지한다.

사전 추정 포함 LLM+임베딩 기록 비용은 **$0.22854392**, 비용 미상 0건이다. test·Grounding Judge·실사용 설정 변경은 실행하지 않았다. 스모크·보조 지표·fallback·비용 전표·지문·원본 해시와 한계는 [결과 문서](../eval/rag-patterns-v1.md)를 따른다. 고정 순서와 캐시 재사용으로 비용·지연의 순수 인과효과는 미확인이다. 이 ADR의 상태는 실험 중이며 새 제품 패턴을 채택한 결정이 아니다.
