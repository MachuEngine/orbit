# ADR-0011 — 읽기 전용 비서 경로 v0 (첫 평가 대상)

- 상태: 채택 (2026-11-11, 개발자가 단계별 진행을 위임한 범위에서 메인 세션이 결정). 핸들 방식(D8-1)과 프롬프트는 `실험 중`이며 3단계-E 파일럿과 8단계 패턴 비교에서 바꿀 수 있다
- 작성일: 2026-11-11
- 근거: ADR-0008(Connector 계약), ADR-0009·0010(평가 기반, 구조화된 답), 세부 설계 D6-1·D8-1 (비공개, `private-docs/`)

## 결정
- 제품 코드 `orbit.assistant`에 읽기 전용 질의 경로를 둔다. 평가 러너에 의존하지 않고, 러너 쪽 어댑터(`orbit.evalrunner`의 SUT)가 이 경로를 감싼다.
- 입력: 사용자 발화, 현재 시각(`Clock.now()`), 사용자 시간대(v0는 설정값 `Asia/Seoul`), 메일·캘린더 커넥터, LLM, 단계 한도 콜백.
- **작업 집합 핸들(D8-1)**: 도구 결과의 일정·메일은 대화 범위의 짧은 핸들(`E1`, `M1`)과 요약 필드로만 모델에 보인다. 제공자 ID는 모델 입력에 넣지 않는다. 도구 인자의 핸들은 코드가 ID로 바꾸고, 모르는 핸들은 오류로 돌려준다.
- **도구는 읽기 전용만** 정의한다: 일정 기간 조회, 일정 상세, 메일 검색(ADR-0008 검색 부분집합), 메일 읽기, 답 제출. 쓰기 도구는 모델에 주지 않는다.
- **외부 콘텐츠(D6-1)**: 메일 본문·일정 설명은 데이터 표지로 감싸고 길이 상한을 둔다. 제목·이름·장소 같은 짧은 외부 필드는 길이 상한만 둔다. 시스템 프롬프트는 도구 결과의 모든 텍스트 필드를 지시가 아닌 데이터로 다루라고 적는다. URL을 가져오는 기능은 없다.
- **답 제출**: 모델은 `submit_answer`로 핸들 기반 답을 낸다. 코드가 핸들을 ID로 바꿔 ADR-0010 형식의 구조화된 답을 만든다. 제출 응답에 텍스트가 없으면 도구 없이 한 번 더 호출해 사용자에게 보일 답을 받는다.
- **프롬프트 정책**: 캘린더가 일정의 최신 상태라는 점은 제품 정책으로 프롬프트에 둔다. 평가 데이터의 특정 함정을 겨냥한 지시(예: 취소 일정 제외)는 넣지 않는다. 생성 온도는 0으로 고정한다.
- 프롬프트는 버전 상수(`PROMPT_VERSION`)로 관리하고 결과의 설정 지문에 들어간다.
- 로그·예외 메시지에 메일·일정 원문을 남기지 않는다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 모델에 제공자 ID 노출 | ID 환각·오타가 다른 대상 조작으로 이어진다(D8-1). 쓰기 경로(4단계)에서 같은 구조를 재사용한다 |
| LangGraph로 v0 구현 | 읽기 전용 단일 루프에는 체크포인트·interrupt가 필요 없다. 승인 대기가 생기는 4단계에서 도입한다(ADR-0003) |
| 평가 러너 안에 구현 | 제품 경로와 평가 대상이 달라져 측정 결과가 제품을 대표하지 못한다 |
