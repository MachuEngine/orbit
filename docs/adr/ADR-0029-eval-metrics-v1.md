# ADR-0029 — 평가 지표 확장과 실행 기록 (v1 기준선 전)

- 상태: 채택 (2026-11-16 개발자 지시: "지금 측정 안되는 지표 모두 측정되도록 수정해서 진행")
- 작성일: 2026-11-16
- 근거: 평가 계획 §1(`docs/evaluation-plan-draft.md`), ADR-0009·0010(채점), ADR-0023(runflow 평가), ADR-0026(평가 스위트 v1)

## 문제
평가 계획 §1에 정의한 지표 중 러너가 재지 않는 것이 많다. 결과 행에는 도구 이름·인자·구조화된 답만 있고, 도구 결과 본문·답 문장·인용 핸들·결함 주입 시점이 없다. 이대로 기준선을 측정하면 지표를 추가할 때마다 비용을 들여 다시 실행해야 한다.

## 결정

### 1. 실행 기록을 먼저 넓힌다 (다시 실행하지 않고 지표를 더할 수 있게)
에피소드 결과 행에 다음을 남긴다. 평가 데이터는 합성이고 결과 파일(`runs/`)은 git에서 제외한다(ADR-0026 §7.3과 같은 근거). 실사용 DB·그래프 상태 규칙(ADR-0006)과는 무관하다.
- 턴별 사용자 발화와 최종 답 문장, 구조화된 답 원본
- 도구 호출마다: 이름, 인자, 결과 본문(모델에 보여 준 그대로, 호출당 상한 8,000자), 오류 종류, 결함 주입 여부와 규칙 이름, 지연
- 답이 가리킨 핸들과 그 핸들이 가리키는 아티팩트 ID(작업 집합 대응표)
- 턴별 구조화된 답(다중 턴)

### 2. 코드로 채점하는 지표 (사후 계산, `stats` 확장)
| 계획 | 지표 | 정의 |
| --- | --- | --- |
| §1-1 | 쓰기 인자 정확도 | 기대 변화 필드(수신자·제목·시각·참석자·장소)별 일치율 |
| §1-1 | 다중 턴 | 대화 단위 성공률(기존 판정). 턴 단위 정답이 없는 턴은 재지 않는다고 명시 |
| §1-2 | 사실 근거율(코드 부분) | 답 문장의 날짜·시각·금액·숫자·이메일·사람 이름 후보를 뽑아, 정규화해 그 에피소드 도구 결과에 있는지 대조. 근거 있음 / 전체 |
| §1-2 | 인용 정확도 | 답의 핸들이 가리킨 아티팩트 vs 과제 `ref_*` 태그. precision·recall |
| §1-2 | 답할 수 없는 질문 | 기권률(정답 기권), 환각률(기권 과제에서 기권하지 않고 답함), 과잉 거절률(답할 수 있는 과제에서 기권) |
| §1-3 | 도구 선택 정확도 | 유형별 기대 도구 집합(데이터 영역: 일정·메일·문서·쓰기·리마인더) 대비 recall, 잘못된 영역 도구 호출 비율 |
| §1-3 | 인자 유효율 | 도구 호출 중 인자·형식 오류(잘못된 핸들, 스키마 오류, 시간대 없는 시각)가 아닌 비율 |
| §1-3 | 불필요한 호출 | 과제별 최소 호출 수(정답 제출 오라클의 호출 수) 대비 초과 호출 수 |
| §1-6 | 결함 주입 | 결함 과제 성공률, 정직 보고율(결함으로 실패한 에피소드 중 답에서 실패를 알린 비율), 결함 상황 환각률(실패 후 근거 없는 사실을 답한 비율) |
| §1-6 | 표현 변형 | 원본·변형 짝의 성공 일치율과 정답률 차이, 구조화된 답 일치율 |
| §1-7 | 효율 | 성공 1건당 비용, 지연 p50·p95, 과제당 도구 호출 수 |
- 정직 보고와 실패 언급은 정해진 표현 목록과 구조화된 답(기권·오류 보고)으로 판정한다. 목록 기반 판정의 한계(놓침)는 보고서에 적는다.

### 3. Judge가 필요한 지표는 기록만 하고 나중에 채점한다
- 서술형 주장의 근거성(§1-2)은 Judge가 필요하다. 계획대로 사람 라벨 표본과의 일치도(kappa ≥ 0.6)를 먼저 검증해야 한다.
- 이번에는 Judge 입력(답 문장·도구 결과 본문)을 기록만 한다. Judge 채점은 기록된 결과에 사후로 적용하므로 기준선을 다시 실행하지 않는다. 범위·비용은 개발자 확인 후 정한다.

### 4. 범위 밖
- 안전(§1-5)은 안전 세트가 없어 가드레일 실험 단계에서 한다.
- 검색 종단 지표(§1-4 종단)는 RAG 비교 실험에서 색인을 켠 실행으로 잰다.
- 음성(§1-8)은 별도.

## 영향
- 결과 파일이 커진다(도구 결과 본문). `runs/`는 git 제외라 저장소에는 영향이 없다.
- v0 결과 파일은 새 필드가 없으므로 새 지표는 "기록 없음"으로 표시하고 비교에 섞지 않는다.
- 이 변경 뒤 assistant_v0·runflow_v0의 luna 기준선을 dev에서 한 번 측정한다(중단한 이전 실행은 버린다).
