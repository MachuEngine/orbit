# 실사용 경로 평가 첫 비교: `runflow_v0` vs `assistant_v0` (2026-11-15)

근거: ADR-0023 §9. 회귀 확인이며 비교 실험이 아니다. 합성 데이터(평가 데이터 v0)만 썼다.

## 설정
- 데이터: `orbit-eval@v0/dev` 36문항(일정 조회만, 묶음 6개), 반복 1회, 시드 0
- 모델: `openai/gpt-6-luna`, reasoning effort `low`(ADR-0015 실험 기본), 같은 단가표
- 코드: `eaaa1f7`. `runflow_v0` = `runflow-v0.7` + `eval-answer-v1` + 색인 끔, `assistant_v0` = `assistant-v0.3`
- 실행: 개발자 로컬, 평가 DB `orbit_eval`

## 결과
| 지표 | `assistant_v0` | `runflow_v0` |
| --- | --- | --- |
| 성공률(묶음 bootstrap 95% CI) | 83.3% (69.2–97.1) | 61.1% (45.5–75.8) |
| 실패: 형식(`answer_format`) / 오답(`wrong_answer`) | 4 / 2 | 10 / 4 |
| 승인 위반, 예상하지 않은 상태 변화 | 0 / 0 | 0 / 0 |
| 비용 합계 | 0.021달러 | 0.017달러 |
| 에피소드당 입력 토큰 중앙값 | 5,120 | 10,043 |
| LLM 호출 수 중앙값, 지연 중앙값 | 3회, 5.1초 | 3회, 5.0초 |
| 추론 토큰 합계 | 667 | 97 |

짝지은 차이(`runflow_v0` − `assistant_v0`): −22.2%p (95% CI −30.2 – −12.5, 묶음 6개라 불안정).

## 해석
- 실사용 경로가 같은 문항에서 더 낮게 나왔다. 반복 1회, 묶음 6개라 크기는 불확실하지만 신뢰구간이 0을 포함하지 않는다.
- `runflow_v0` 실패 14건 중 10건이 형식 실패다. 대부분 답 종류를 잘못 골랐다. 인물의 다음 미팅(`event`)에 빈 `event_set`을 내거나, 변경된 일정의 최신 시각(`event_time`)에 `event`를 냈다.
- 두 경로의 차이가 원인 후보로 셋 있고, 이번 실행으로는 서로 구분할 수 없다.
  1. 프롬프트: `assistant_v0`에는 [사실 확인] 구역(캘린더가 최신 상태, 하루 조회 범위, 상대 날짜 계산, 추측 금지)과 답 종류 목록이 있다. `runflow` 프롬프트에는 이 구역이 없고, 답 종류는 평가용 안내 한 단락에만 있다.
  2. 추론: `runflow`는 OpenAI 추론 항목을 다음 요청에 되돌려 보내지 않는다(ADR-0023 타당성 위협). 추론 토큰이 97 대 667로 크게 적다.
  3. 도구 수: `runflow`는 도구 14개(답 제출 포함), `assistant_v0`는 5개다.
- 비용은 `runflow`가 입력 토큰이 2배인데도 캐시 덕에 더 낮았다. 사전 추정(0.10~0.15달러)보다 훨씬 적었다.

## 다음 확인
- 원인을 가르려면 한 요소씩 바꾼 ablation(프롬프트 [사실 확인] 구역 추가, 추론 항목 되돌리기)을 v0 dev에서 반복 3회로 돌린다. 이는 평가 데이터 v1 전에 실사용 경로의 품질 문제를 확인하는 일이다.
