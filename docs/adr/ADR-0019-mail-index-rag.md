# ADR-0019 — 메일 색인과 검색 (RAG v0)

- 상태: 구조는 채택, 검색 방식(임베딩 모델·혼합 방식·청크 크기·RRF 값)은 `실험 중`. 비교는 평가 보류 목록 "RAG 방식 비교"에서 한다.
- 작성일: 2026-11-12
- 근거: 세부 설계 D4-1·D4-2·D4-4·D7-1~D7-4(비공개 `private-docs/`), ADR-0004(RLS), ADR-0005(작업 큐), ADR-0006(RLS 밖 저장소), ADR-0008(커넥터 계약), ADR-0011(핸들), ADR-0016(연결), ADR-0018(데이터 봉투)

## 문제
지금 메일 조회는 Gmail 검색 문법 부분집합(`from:`, `subject:` 등)으로만 한다. "지난달 견적 얘기한 메일"처럼 표현이 정확히 맞지 않거나 여러 메일을 종합해야 하는 질문은 찾지 못한다. 반대로 메일 전체를 서버에 복제하면 저장·삭제 전파·보안 부담이 커진다(D7-1).

## 결정

### 1. 색인 범위 (D7-1)
- 이번 단계의 색인 대상은 Gmail 메일 본문이다. 문서는 10단계에서 같은 테이블에 `kind`만 달리해 넣는다. 일정은 색인하지 않는다(실시간 조회가 더 정확하다).
- 연결해도 아무것도 색인하지 않는다. 사용자가 연결 화면에서 라벨과 기간(30·90·365일)을 골라야 색인한다. 범위는 연결별로 여러 개 둘 수 있다.
- 비용 상한: 범위 하나의 첫 동기화는 최근 메일부터 최대 2,000통, 메일 하나는 본문 앞 20,000자·청크 20개까지 색인한다. 값은 상수 한곳에 둔다.

### 2. 커넥터 계약 확장 (ADR-0008 4절 추가)
`MailConnector`에 다음을 추가한다. Sim과 Google Adapter가 같은 계약 테스트를 통과해야 한다.
- `list_labels()`: 라벨 ID·이름·종류(system/user)
- `list_message_ids(label_id, *, after, page_token)`: 라벨·기간 안의 메시지 ID(최근순) 페이지
- `current_history_id()`: 지금 시점의 변경 이력 위치
- `list_history(start_history_id, *, page_token)`: 이후 추가된 메시지, 삭제된 메시지, 라벨이 붙거나 빠진 메시지. 이력이 만료됐으면 `HistoryExpired`(새 계약 오류)를 던지고, 호출자는 전체 동기화로 돌아간다(D7-2).

새 OAuth 권한은 필요 없다(`gmail.readonly`로 모두 가능).

### 3. 저장 (마이그레이션 0008, 모든 테이블 RLS ENABLE + FORCE)
| 테이블 | 내용 |
| --- | --- |
| `index_scope` | 연결별 색인 범위(라벨 ID, 라벨 이름, 기간 일수) |
| `sync_state` | 연결별 동기화 위치(`history_id`), 마지막 동기화 시각, 상태, 오류 종류 |
| `source_item` | 색인한 메일 한 통(제공자 메시지 ID, 스레드 ID, 제목, 보낸 사람, 날짜, 라벨 ID 목록, 본문 해시, 색인 시각). `(connection_id, provider_item_id)` 유일 |
| `chunk` | 검색 단위(본문 조각, 형태소 토큰 `tsvector`, `vector(1536)` 임베딩, 임베딩 모델 ID). `source_item` 삭제 시 CASCADE |

- 모든 행에 `workspace_id`·`connection_id`를 둔다. 인덱스는 `chunk.embedding` HNSW(cosine), `chunk.tokens` GIN.
- 그래프 상태와 작업 인자에는 `workspace_id`·`connection_id`만 둔다(ADR-0006). 로그에는 개수·ID·오류 종류만 남긴다.

### 4. 색인
- 청크: 제목과 본문을 이어 약 800자 단위, 100자 겹침으로 자른다(`실험 중`).
- 한국어 키워드: Kiwi(`kiwipiepy`)로 형태소를 분석해 내용어 토큰을 `simple` 설정 `tsvector`로 저장한다(D4-2). 질의도 같은 분석기로 토큰화한다.
- 임베딩: OpenAI `text-embedding-3-small`(1536차원, `실험 중`). 모델 ID는 설정과 설정 지문에 넣고 청크마다 저장한다. 테스트는 결정적 가짜 임베더를 쓴다.
- 본문이 바뀌지 않았으면(해시 같음) 다시 임베딩하지 않는다.

### 5. 검색 (D4-1·D4-4, `실험 중`)
SQL 한 문장에서 `workspace_id`로 거른 뒤 벡터 거리 상위 50개와 키워드 점수(`ts_rank`) 상위 50개를 뽑고, RRF(k=60)로 합쳐 메일 단위로 묶은 상위 결과를 돌려준다. RLS가 같은 조건을 DB에서 한 번 더 강제한다. 필터와 HNSW를 함께 쓸 때 결과가 모자라지 않게 pgvector 0.8의 반복 스캔(`hnsw.iterative_scan`)을 켠다. `ts_rank`는 BM25가 아니며, BM25 기준선은 평가에서 따로 계산한다.

### 6. 동기화 (D7-2·D7-3)
- Procrastinate 작업 `sync_mail_index(workspace_id, connection_id)`. 범위를 저장하거나 사용자가 "지금 동기화"를 누르면 등록하고, 주기 작업이 마지막 동기화가 15분 넘은 연결을 골라 등록한다. 워크스페이스를 가로질러 대상을 고르는 일은 ID만 돌려주는 `SECURITY DEFINER` 함수 하나로 한다.
- 첫 동기화는 범위별 메시지 ID 목록으로, 이후는 `list_history`로 증분 동기화한다. 이력 만료면 전체 동기화.
- 질의 직전 동기화: 검색 도구는 마지막 동기화가 5분보다 오래됐으면 시간 상한(10초) 안에서 증분 동기화를 먼저 한다. 넘으면 있는 색인으로 검색한다.
- 같은 연결의 동기화는 advisory lock으로 직렬화한다.
- 최신성: 검색 결과에 `indexed_as_of`(마지막 동기화 시각)를 넣고, 프롬프트는 색인 결과로 답할 때 "몇 분 전 기준"을 함께 적게 한다. 연결 화면에도 마지막 동기화 시각을 보인다.

### 7. 삭제 전파 (D7-4)
- 연결 해제: 연결을 `revoked`로 바꾸는 같은 트랜잭션에서 그 연결의 `index_scope`·`sync_state`·`source_item`·`chunk`를 지운다. 남은 행 0을 자동 테스트로 확인한다.
- 증분 동기화에서 메일 삭제가 오거나 메일이 어느 범위 라벨에도 속하지 않게 되면 그 `source_item`과 청크를 지운다.
- 범위를 지우면 남은 범위 어디에도 속하지 않는 항목을 같은 트랜잭션에서 지운다.
- 보존 기간: 동기화마다 보낸 날짜가 자기 범위들의 기간(가장 긴 것) 밖으로 밀린 항목을 지운다. 기간을 줄이면 다음 동기화에서 정리된다.
- 소프트 삭제는 쓰지 않는다. 대기 중인 동기화 작업은 대상이 없으면 아무것도 하지 않고 끝난다.

### 8. 비서 도구
- 실사용 경로(`runflow`)에 읽기 도구 `search_indexed_mail(query, max_results)`를 추가한다. 결과 메일은 작업 집합에 M 핸들로 등록해 `read_mail`로 이어서 읽을 수 있다. 결과는 다른 도구 결과처럼 데이터 봉투로 감싼다(ADR-0018).
- 기존 `search_mail`(Gmail 검색)은 그대로 둔다. 프롬프트는 날짜·보낸 사람처럼 조건이 분명하면 `search_mail`, 내용·주제로 찾을 때는 `search_indexed_mail`을 쓰라고 안내한다. 색인 범위가 없으면 도구는 `index_empty`를 돌려준다.
- 평가 경로(`assistant_v0`)에는 등록하지 않는다. v0 회귀에 영향이 없고, 방식 비교는 평가 보류 목록에서 한다.

## 결과
- 새 의존성: `kiwipiepy`. pgvector Python 패키지 없이 SQL 리터럴로 벡터를 넘겨도 된다(구현이 정한다).
- 프롬프트 `runflow-v0.5`.
- 메일 본문이 임베딩을 위해 OpenAI로 전송된다. 이미 답 생성에 같은 제공자로 본문을 보내고 있어 새 수신자는 생기지 않는다. 제공자를 바꿀 때 함께 검토한다.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 연결 즉시 전체 색인 | 저장·삭제·비용·보안 부담이 가장 크다(D7-1) |
| 벡터만 또는 키워드만 | 한국어 고유명사·코드 검색과 표현이 다른 의미 검색을 함께 다루려면 혼합이 무난하다. 우열은 평가에서 잰다 |
| `text-embedding-3-large`, 로컬 모델 | 비용·차원(halfvec 필요) 또는 의존성·속도 부담. 비교 실험 후보로 남긴다 |
| 별도 벡터 DB | 권한 필터와 삭제가 두 저장소로 갈라진다(D4-1) |
| Gmail 푸시(Pub/Sub) | 공개 수신 엔드포인트·watch 갱신이 필요하다. 12단계 운영에서 검토 |
