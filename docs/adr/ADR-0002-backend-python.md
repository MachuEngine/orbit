# ADR-0002 — 백엔드 언어: Python

- 상태: 채택 (2026-11-10, 개발자 결정)
- 관련 문서: `docs/architecture.md` §3, 세부 설계 D3-1·D5-3·D7-5·D9-2 (비공개, `private-docs/`)

## 배경

세부 설계의 여러 후보 기술이 Python을 전제로 한다. Agent 실행(LangGraph), DB 접근(SQLAlchemy), 작업 큐(Procrastinate), 한국어 형태소 분석(Kiwi), 평가 러너가 모두 Python 생태계에 있다. 언어를 정해야 스파이크와 백엔드 골격 작업을 시작할 수 있다.

## 결정

백엔드와 평가 러너를 Python으로 작성한다.

| 항목 | 선택 | 상태 |
| --- | --- | --- |
| 언어 | Python | 채택 |
| 버전 | 3.12 | 스파이크에서 사용, 백엔드 골격 작업 때 확정 |
| 패키지·가상환경 관리 | uv (`pyproject.toml` + `uv.lock`) | 스파이크에서 사용, 백엔드 골격 작업 때 확정 |

- 3.12를 쓰는 이유: 로컬에 3.12·3.14가 있으며, 3.14는 나온 지 얼마 안 되어 일부 라이브러리의 바이너리 휠이 늦게 나올 수 있다. 확정 전에 주요 의존성의 3.13 이상 지원을 다시 확인한다.
- uv를 쓰는 이유: 잠금 파일로 의존성 버전을 고정해 실험 재현성(D3-2 설정 지문)을 지키기 쉽다.

## 검토한 대안

| 대안 | 장점 | 채택하지 않은 이유 |
| --- | --- | --- |
| TypeScript(Node) 백엔드 | 프론트엔드와 언어 통일 | LangGraph JS는 Python판보다 기능이 늦게 들어오고, Procrastinate·Kiwi 같은 후보 기술의 대체재를 다시 골라야 한다 |
| 백엔드 TypeScript + 평가 러너 Python | 각 영역에 맞는 언어 | 평가 대상이 Orbit 파이프라인 전체(D3-1)라서 러너와 백엔드가 같은 코드를 직접 불러야 한다. 언어를 나누면 이 경계가 HTTP로 바뀐다 |

## 결과

- `scripts/check.sh`의 백엔드 검사(lint·type check·test)는 Python 도구로 채운다. 도구는 백엔드 골격 작업 때 정한다.
- 프론트엔드 스택은 이 결정과 별개로 미결정이다.
