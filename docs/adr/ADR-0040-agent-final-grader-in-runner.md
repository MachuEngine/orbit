# ADR-0040 — Agent 최종 채점기를 평가 러너에 넣기

- 상태: 채택 (2026-11-24)
- 작성일: 2026-11-24
- 근거: ADR-0039(Jev 정답 판정), [results-v1](../eval/results-v1.md)의 Agent 채점 감사와 "구조화 답 종류 오채점 재판정", [experiments C01·C02](../eval/experiments.md)

## 문제

Agent 성공률의 주 점수는 2026-11-24 개발자 결정으로 다음 규칙이 됐다.

- 상태 변화·승인·도구·구조화 답은 코드로 검사한다.
- 답 본문의 문자열 검사(`answer_facts`, `must_not_contain`)는 Jev v4가 대신한다.
- Jev 판정이 코드 문자열 판정과 다르거나 경계 확률이면 Gemini 정답 비교 Judge가 최종 판정한다.

이 규칙은 지금 임시 스크립트로만 돌린다. 새 평가를 실행하면 러너는 옛 문자열 검사로 성공 여부를 기록한다. 그래서 개선 실험마다 같은 재채점을 손으로 다시 해야 하고, 실험마다 규칙이 조금씩 달라질 수 있다.

## 결정

### 1. 러너 실행 뒤에 채점 단계를 둔다

- `run`은 결과 JSONL(`<out>`)을 지금처럼 쓴다. 코드 채점 결과(`outcome`)는 바꾸지 않는다.
- 실행이 끝나면 채점 단계가 `<out 이름>.graded.jsonl`을 새로 쓴다. 행 구성은 결과 행과 같다. `outcome.success`와 `outcome.failure_type`만 최종 판정으로 바꾸고, 판정 근거는 `grade` 필드에 남긴다.
- `stats`, `stats --compare`, `rag-diag`는 `.graded.jsonl`을 그대로 읽는다. 통계 코드는 바꾸지 않는다.
- 이미 있는 결과 파일은 새 하위 명령 `grade`로 채점한다. 원래 결과 파일은 고치지 않는다.
- `--live-llm` 실행은 채점을 기본으로 켠다. 끄려면 `--grade off`를 준다. 채점 비용 상한(`--max-grade-cost-usd`)이 없으면 실행 전에 거부한다.
- `--llm-script` 실행(CI 스모크)은 기본으로 채점하지 않는다. 외부 호출과 비용이 없어야 하기 때문이다.

### 2. 판정 규칙 (C01·C02와 같다)

정답 사실(`gold.answer_facts`)이 없는 과제는 코드 판정을 그대로 쓴다. 사실이 있는 과제는 아래 순서로 판정한다.

1. **Jev 적용 대상**: 다음 중 하나인 에피소드
   - 코드 판정이 성공이다.
   - 틀린 검사가 `answer_facts`·`must_not_contain`뿐이다.
   - 실패 유형이 `answer_kind`이고, 정답 종류가 `event_time`, 답 종류가 `event`, 답의 일정 ID가 정답과 같으며, 틀린 검사가 `structured_answer`·`answer_facts`·`must_not_contain` 안에 있다(C02 규칙). `event`와 `event_set`의 차이는 실제 실패로 둔다.

   대상이 아니면 코드 판정을 그대로 쓴다.
2. **Jev v4**: `typesafe-ai/jev-1.14.0`, 프롬프트 `jev-correctness-v4-extra`, 사실별 확률 최솟값이 0.25 이상이면 정답이다.
   - 질문은 사용자 턴을 합친다. 턴이 여럿이면 `"1번째 요청: …"` 형식으로 이어 붙인다.
   - 사실 설명이 겹치는 과제(일정 목록)에서는 `"일정 시작 시각"` 설명 앞에 바로 앞 일정 제목을 붙인다(`"'제목' 일정의 시작 시각"`). 설명이 겹치지 않는 과제는 설명을 그대로 쓴다.
   - Gemini 입력은 설명 겹침과 관계없이 제목을 붙인다. C01·C02에서 측정한 방식과 같게 하려는 것이다.
3. **Gemini 2차 판정**: 아래 경우 `google/gemini-3.6-flash`, 프롬프트 `correctness-v2`(설정 `eval/graders/gemini-correctness-v2.toml`)의 판정을 최종으로 쓴다.
   - Jev 판정이 코드 문자열 판정과 다르다. 코드 문자열 판정은 `text_fact_recall == 1`이고 `must_not_contain`이 실패하지 않은 경우를 정답으로 본다.
   - Jev 확률 최솟값이 [0.1, 0.6) 안에 있다.
4. **최종 판정**: Jev 적용 대상이면 답 본문 판정(Gemini 또는 Jev)이 정답일 때 성공이다. 오답이면 `failure_type`은 `wrong_answer`다. 다만 원래 코드 실패 유형이 `answer_kind`이고 본문이 오답이면 `answer_kind`를 유지한다.
5. 답 문장이 비어 판정할 수 없으면 `success`는 `null`이다. 통계는 이 에피소드를 분모에서 빼고 개수를 따로 보고한다(기존 규칙).
6. Jev·Gemini 호출이 실패하거나 비용 상한에 걸려 판정이 빠진 에피소드가 있으면 `.graded.jsonl`을 쓰지 않고 코드 3으로 끝낸다. 받은 판정은 `.grade/`에 남으므로 `grade`를 다시 실행하면 빠진 건만 호출한다.
7. 결과에 test 분할 행이 있으면 `grade`도 `run`과 같은 봉인 해제 플래그를 요구한다. 정답 사실이 외부 Judge 프롬프트로 나가기 때문이다.

감사용 표본(사람 판정 62건, 무작위 100건)은 러너에 넣지 않는다. 규칙의 오류율 추정은 C01에서 이미 했다.

### 3. 재현성

- `grade` 필드에 채점기 지문을 넣는다. 지문은 판정 규칙 버전·Jev 모델 ID·프롬프트 버전·임계값·Gemini 모델 ID·프롬프트 SHA·경계 구간을 묶은 해시다. 판정 규칙(대상 선정, 코드 문자열 판정, 제목 붙이기)을 바꾸면 규칙 버전을 올린다.
- 기존 라이브 스모크(`eval-smoke-live`)와 RAG 패턴 스크립트는 `--grade off`로 실행한다. 회귀 확인용이거나 RAG 과제 전용 채점을 따로 쓰기 때문이다.
- Jev·Gemini 원 응답은 `<out 이름>.grade/` 폴더의 `jev.jsonl`, `correctness.jsonl`에 쌓는다. 기존 이어하기 규칙(같은 키는 다시 부르지 않음)을 그대로 쓴다.
- 같은 결과 파일을 다시 채점하면 저장된 판정을 재사용하므로 결과가 같다.

## 대안

- **채점 결과를 원래 결과 파일에 덮어쓰기**: 코드 판정 기록이 사라지고 이미 있는 파일은 쓰지 않는다는 러너 규칙과 충돌한다. 기각.
- **`stats`가 옆 파일을 찾아 판정을 바꿔 끼우기**: 통계 코드 세 곳(`stats`, `compare`, `rag-diag`)을 모두 고쳐야 한다. 파일 하나를 새로 쓰는 쪽이 변경이 작다. 기각.
- **에피소드마다 바로 채점**: 실행 중 외부 호출이 늘고 실패 처리가 SUT 실행과 섞인다. 기각.

## 영향

- 개선 실험은 `.graded.jsonl`의 성공률로 비교한다. 기존 공개 수치(C02 최종값)와 같은 규칙이다.
- 채점 비용: v1 전체 재채점 기준 Jev는 에피소드당 약 0.00002달러, Gemini는 갈림·경계 건에만 부른다. 실행 전 추정치를 출력하고 상한을 넘으면 중단한다.
- 키: `AI_GATEWAY_API_KEY`(Jev), `ORBIT_OPENROUTER_API_KEY` 등 Gemini 경로 키가 필요하다. 없으면 실행 전에 거부한다.
