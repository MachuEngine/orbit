# Orbit UI 디자인 검토

> 검토자는 코드를 고치지 않는다. 문제와 수정 방향만 보고하고, 수정은 implementer가 한다.
> 이 점검표는 코드만 읽고도 쓸 수 있어야 한다. 브라우저 확인은 할 수 있을 때 더하는 보조 수단이다.
> code-reviewer는 Skill 도구가 없으므로 이 파일을 Read로 읽어서 쓴다.

## 검토 전에 읽을 것
- `docs/brand/brand-guide.md`, `docs/brand/tokens.css` (없으면 토큰 준수 영역은 "토큰 없음"으로 적고, 하드코딩 값만 목록으로 남긴다)
- 변경과 관련된 ADR, 작업 명세
- 바뀐 컴포넌트를 쓰는 화면과 공용 스타일 (diff만 보고 판단하지 않는다)

## 중요도
| 중요도 | 기준 |
| --- | --- |
| 높음 | 출시 차단. 보안 규칙(D6-1) 위반, 승인 없이 쓰기가 실행되는 것처럼 보이는 화면, 주요 동작을 키보드로 할 수 없음, 본문 대비 기준 미달, 한글 입력 중 Enter로 전송됨 |
| 중간 | 일부 사용자가 막히거나 오해한다. 아이콘 버튼 이름 없음, 390px에서 가로 스크롤, 토큰 밖 색·글자 크기, 오류 문구가 다음 행동을 알려 주지 않음 |
| 낮음 | 일관성·완성도 문제. 문체 혼용, 생성형 기본 디자인, 불필요한 장식 모션 |

실제로 문제가 생기는 사용자·화면 상황을 설명할 수 있을 때만 지적한다. 취향 차이는 지적하지 않는다.

## 점검표

### 1. 접근성
- 색 대비: 글자·UI 요소 색이 토큰에서 오고, 토큰 조합이 브랜드 가이드 대비표에서 통과한 조합인지 본다. 대비표에 없는 새 조합이면 지적한다(본문 4.5:1, 큰 글자·UI 요소 3:1).
- 포커스 표시: `outline: none`이나 `outline: 0`을 쓴 곳에 `:focus-visible` 대체 스타일이 있는지 본다.
- 포커스 순서: 모달·승인 화면이 열리면 포커스가 그 안으로 들어가고, 닫히면 연 버튼으로 돌아오는지 본다. 모달이 열린 동안 뒤 화면으로 포커스가 빠지지 않는지 본다. 양수 `tabindex`가 없는지 본다.
- 모션: 애니메이션·전환이 `prefers-reduced-motion: reduce`에서 꺼지거나 줄어드는지 본다. 토큰의 모션 값을 쓰면 토큰에서 처리된다.
- 폼 이름표: 입력창마다 보이는 이름표나 `aria-label`이 있는지 본다. placeholder만으로 이름을 대신하지 않는다. 오류 문구가 해당 입력창과 `aria-describedby`로 연결되는지 본다.
- 아이콘 버튼: 글자 없는 버튼에 화면낭독기용 이름(`aria-label` 등)이 있는지 본다. 장식용 아이콘은 `aria-hidden="true"`인지 본다.
- 실시간 갱신: 채팅 응답 스트리밍, 실행 상태 변화가 화면낭독기에 알려지는지(`aria-live`) 본다. 토큰 하나마다 알리면 낭독이 끊기므로 문장·단계 단위로 알리는지도 본다.

### 2. 반응형
- 폭 390px에서 가로 스크롤이 생기지 않는지 본다. 고정 `width`(px), 줄바꿈 없는 긴 문자열(메일 주소, URL, 파일 이름), 넓은 표가 주된 원인이다.
- 버튼·링크의 누르는 영역이 44×44px 안팎인지 본다.
- 채팅 입력창이 모바일 가상 키보드에 가려지지 않는지 본다(`100vh` 고정 높이는 위험 신호).

### 3. 토큰 준수
- 토큰 파일 밖에서 색을 직접 쓰지 않는다: hex, `rgb()`, `hsl()`.
- 글자 크기·줄 간격·글꼴 묶음을 px나 글꼴 이름으로 직접 쓰지 않는다.
- 간격·모서리·그림자는 토큰이 있으면 토큰을 쓴다. 토큰에 없는 값이 필요하면 토큰 추가를 수정 방향으로 제시한다(brand-identity 스킬).

### 4. 문구
- 버튼 동사가 실제 동작과 같다. "확인", "제출" 대신 "메일 보내기", "일정 변경하기"처럼 무엇이 일어나는지 쓴다.
- 같은 동작은 흐름 끝까지 같은 말을 쓴다. "메일 보내기" 버튼 → "메일을 보냈습니다" 알림. 버튼은 "보내기"인데 알림이 "전송 완료"면 지적한다.
- 오류 문구는 무슨 일이 일어났는지와 사용자가 할 일을 함께 말한다. "오류가 발생했습니다"만 있으면 지적한다.
- 브랜드 가이드가 정한 문체(합니다체·해요체)를 지킨다. 한 화면 안에서 섞지 않는다.
- 번역투와 명사 나열을 피한다. 예: "발송 처리가 완료되었습니다" → "메일을 보냈습니다".
- 빈 화면은 사용자가 처음 할 수 있는 행동을 알려 준다.

### 5. 한글 조판과 입력
- 본문에 `word-break: keep-all`이 있고, 긴 주소·URL용 `overflow-wrap: anywhere`(또는 `break-word`)가 함께 있는지 본다.
- **한글 입력(IME) 조합 중 Enter**: Enter로 전송하는 입력창은 조합 중인 Enter를 무시해야 한다. 키 처리기에서 `isComposing`이 참이거나 `keyCode === 229`이면 전송하지 않는지 본다. 이 검사가 없으면 마지막 글자가 두 번 들어가거나 조합 중인 문장이 잘린 채 전송된다(높음).
- 날짜·시각 표기가 한 형식으로 통일되어 있고, 캘린더 화면에는 시간대가 드러나는지 본다.
- 없는 굵기를 브라우저가 흉내 내지 않도록, 쓰는 `font-weight`가 브랜드 가이드의 굵기 목록 안에 있는지 본다.

### 6. 생성형 기본 디자인
브랜드 가이드가 일부러 고른 것이 아니라면 낮음으로 지적한다.
- 보라·파랑 그라데이션, AI를 뜻하는 반짝이 아이콘, 유리 효과(glassmorphism)
- Inter 단독 사용, 크림색 배경 + 테라코타 강조색
- 같은 모서리·같은 그림자의 카드를 정보 위계와 상관없이 격자로 늘어놓은 구성
- 모든 제목 위의 영문 대문자 작은 라벨, 모든 버튼 끝의 화살표, 아이콘 대신 쓴 이모지
- 화면마다 들어가는 등장 애니메이션

### 7. Orbit 전용: 승인 화면과 쓰기 동작
- **승인 화면에 보여야 하는 것**
  - 대상: 받는 사람 전체, 바꿀 일정, 대상 문서
  - 인자 요약: 제목, 본문 앞부분, 일시 변경 전후
  - 되돌릴 수 있는지: 메일 발송처럼 되돌릴 수 없는 동작은 `danger` 토큰과 문구로 명시
  - 외부 출처 경고: 받는 사람 같은 인자가 사용자 입력이 아니라 메일·문서 본문에서 왔으면 그 인자 옆에 경고를 표시한다(D6-1). 출처 정보를 서버 응답에서 받는지, 화면이 추측하는지 본다.
- 화면에 보이는 인자가 서버가 해시로 고정한 승인 인자와 같은 데이터인지 본다. 클라이언트가 인자를 다시 조립하거나 수정할 수 있으면 높음이다(D5-4).
- 위험 동작이 서버 승인 없이 실행 가능한 것처럼 보이지 않는다. 채팅의 "보내기" 버튼은 승인 요청을 만들어야 하고, 쓰기 API를 직접 부르면 안 된다. 서버가 실행을 확인하기 전에 "보냈습니다" 알림을 띄우지 않는다.
- 상태 표시가 승인 대기 / 실행 중 / 완료 / 실패 / 결과 확인 중을 구분한다. 결과가 불명확한 상태에서 "다시 보내기"를 제공하면 중복 발송이 생기므로 높음이다(D5-5).
- 승인 버튼은 처리 중 비활성화되고, 거절·취소 버튼이 같은 무게로 보인다. 되돌릴 수 없는 동작에서 기본 포커스나 Enter가 승인으로 가지 않는다.

### 8. Orbit 전용: 외부 메일·문서 콘텐츠 렌더링 (D6-1)
- 외부 HTML을 렌더링하는 곳(`innerHTML`, `dangerouslySetInnerHTML`, `v-html`, `{@html}`, `srcdoc`)이 허용 목록 기반으로 정제된 값만 넣는지 본다.
- 원격 리소스를 자동으로 요청하지 않는다. 대상: `<img src>`, CSS `url()`·`@import`, `<link>`, `<iframe>`, `<object>`, `<video>`·`<audio>`, 링크 미리 가져오기. 하나라도 열려 있으면 열람 추적과 정보 유출 경로가 되므로 높음이다.
- 링크는 자동으로 열거나 미리보기를 가져오지 않는다. 실제 이동할 도메인을 보여 주고, 열 때 `rel="noopener noreferrer"`를 쓴다.
- 외부 본문이 Orbit 자체 UI(버튼, 경고, 승인 문구)처럼 보이지 않도록 시각적으로 구분되는지 본다.

## 코드로 찾는 방법
code-reviewer의 Bash 훅은 셸 기호(`| ( ) [ ] { } < > \ & ;` 등)가 든 명령을 막는다. 그래서 정규식 대신 **고정 문자열 하나씩** 찾는다: `git grep -n -F <문자열> -- <경로>`. `<경로>`는 프론트엔드 디렉터리로 바꾼다. 찾은 줄은 주변 코드를 Read로 읽고 판단한다.

| 점검 | 찾을 문자열 (명령 하나에 하나씩) |
| --- | --- |
| 직접 쓴 색 | `#` (결과가 많으면 스타일 파일로 경로를 좁힌다), `rgb`, `hsl` |
| 직접 쓴 글자 크기 | `font-size`, `fontSize` |
| 포커스 제거 | `outline` |
| 모션 | `animation`, `transition`, `prefers-reduced-motion` |
| Enter 처리 | `isComposing`, `keyCode`, `compositionend`, `Enter` |
| 외부 HTML 삽입 | `innerHTML`, `dangerouslySetInnerHTML`, `v-html`, `@html`, `srcdoc` |
| 원격 리소스·링크 | `img`, `iframe`, `url`, `@import`, `_blank` |
| 고정 높이·폭 | `100vh`, `width` |

토큰 파일(`tokens.css`) 안의 결과는 정상이므로 제외하고 본다.

## 브라우저로 확인하기 (가능할 때만)
개발 서버와 브라우저 도구가 있는 메인 세션에서만 한다. code-reviewer는 코드 확인으로 끝낸다.
- 390×844와 1280×800에서 스크린샷을 찍는다. 밝은·어두운 모드를 각각 본다.
- Tab 키만으로 채팅 → 승인 화면 → 승인·거절까지 가 본다.
- 합성 데이터로만 확인한다. 외부 이미지가 든 합성 메일을 열어 네트워크 요청이 생기지 않는지 본다.
- 브라우저로 확인한 항목은 "확인", 코드만 읽고 판단한 항목은 "추정"으로 적는다.

```
### 지적 사항 (중요도 높은 순)
1. [높음|중간|낮음] [확인|추정] 경로:줄 — 문제 한 줄 요약
   - 문제가 생기는 상황: 어떤 사용자가 어떤 화면에서 무엇을 하면 어떤 결과가 나오는지
   - 수정 방향: 무엇을 바꿔야 하는지 (코드는 쓰지 않는다)

### 확인 방법과 확인하지 못한 범위

```
점수는 지적 사항과 맞아야 한다. 높음 지적이 있는 영역은 0점이다. 문제를 찾지 못했으면 "지적 사항 없음"과 확인하지 못한 범위를 적는다.
