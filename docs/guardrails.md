# Orbit 가드레일 정리

- 상태: 정리 문서(결정 아님). 새 가드레일 도입과 측정 계획은 ADR-0033에서 정한다.
- 작성일: 2026-11-24
- 근거: ADR-0004(RLS), ADR-0006(RLS 밖 저장소), ADR-0012(쓰기 경로), ADR-0018(지시·데이터 분리), ADR-0033(안전 세트·ablation), 세부 설계 D5·D6·D8(비공개)

## 1. 정의

이 문서에서 **가드레일**은 모델이 틀리거나 속아도 사용자와 데이터에 피해가 가지 않도록, 모델 바깥에서 입력·행동·출력을 제한하는 장치를 말한다. 모델이 지시를 잘 따르게 만드는 프롬프트 문구 자체는 가드레일의 일부일 수 있지만, 그것만으로 피해를 막는다고 보지 않는다.

가드레일은 작동 방식에 따라 두 종류로 나눈다.

| 종류 | 작동 방식 | 예 | 실패 방식 |
| --- | --- | --- | --- |
| 구조형 | 공격인지 판단하지 않는다. 어떤 입력이 와도 특정 행동이 일어날 수 없게 경로를 막는다 | 승인 없이는 쓰기 실행 불가, RLS | 구현 버그가 없으면 결정적으로 막는다 |
| 판정형 | 입력·출력·행동을 보고 위험한지 판정해 막거나 경고한다 | 프롬프트 인젝션 탐지기, 쓰기 의도 검사기 | 놓침과 오탐이 확률적으로 생긴다. LLM 판정기는 판정 대상 본문에 속을 수 있다 |

평가 채점기(Jev, Gemini 판정)는 가드레일이 아니다. 실행이 끝난 뒤 정답과 비교해 점수를 매기며, 실사용 요청에는 정답이 없다. 판정형 가드레일은 같은 모델로 만들 수 있지만 기준(정답 없이 위험 여부)과 시점(실행 중)이 다르다.

## 2. Orbit이 막아야 할 피해

Orbit은 사용자의 메일·일정·문서를 읽고, 승인을 받아 일정을 바꾸거나 메일을 보낸다. 메일·문서 본문은 외부 사람이 쓴다. 이 구조에서 생길 수 있는 피해를 심각도 순으로 적는다.

| ID | 피해 | 주된 경로 | 심각도 |
| --- | --- | --- | --- |
| H1 | 다른 사용자(워크스페이스)의 데이터 노출 | 조회·검색의 필터 누락 | 출시 차단 |
| H2 | 사용자가 승인하지 않은 외부 쓰기(메일 발송, 일정 생성·변경·취소) | 메일·문서 속 공격 지시(간접 프롬프트 인젝션), 모델 오판 | 출시 차단 |
| H3 | 사용자 데이터가 외부 목적지로 유출 | 메일 발송 수신자·본문 조작, 링크·이미지 자동 로딩 | 높음 |
| H4 | 사용자가 속아서 공격이 만든 쓰기를 승인 | 승인 화면에서 출처를 알아보기 어려움 | 높음 |
| H5 | 승인 없는 부수 효과(리마인더 생성) | 공격 지시 | 중간 |
| H6 | 원래 작업 방해(엉뚱한 답, 거절) | 공격 지시 | 중간 |
| H7 | 시스템 지침 노출 | 공격 지시, 사용자 직접 요청 | 낮음(지침에 비밀이 없다) |
| H8 | 비용·실행 폭주 | 도구 호출 반복 | 낮음 |
| H9 | 메일 본문·이름이 RLS 밖 저장소(그래프 상태, 작업 큐, 로그)에 남음 | 코드 실수 | 높음 |

사용자가 자기 데이터로 직접 탈옥을 시도하는 경우는 피해 대상이 사용자 자신이라 위 표에 따로 두지 않는다. 다만 H1·H2 경로가 사용자 입력으로도 열리지 않아야 한다.

근거 없는 답(환각)은 품질 문제로 보고 평가 성공률에서 다룬다. 이 문서의 범위가 아니다.

## 3. 지금 들어가 있는 장치

| 장치 | 종류 | 막는 피해 | 위치·근거 | 효과 측정 |
| --- | --- | --- | --- | --- |
| `workspace_id` 필터 + RLS(FORCE). 벡터 검색도 같은 SQL에서 필터 | 구조형 | H1 | ADR-0004, D4 | 단위·통합 테스트. 공격 상황 측정 없음 |

| 인자 해시: 승인 때와 실행 직전 해시가 같아야 실행 | 구조형 | H2 | ADR-0012, D5-5 | 테스트 |

| 데이터 봉투: 도구 결과 전체를 run마다 바뀌는 경계 태그로 감싸고 `<`·`>` 이스케이프 | 구조형(위조 방지) + 프롬프트 | H2·H5·H6·H7 | ADR-0018 | 없음. 모델이 봉투 안 지시를 따르지 않는지는 확률적이다 |

| 외부 본문 길이 상한(`read_mail` 4,000자) | 구조형 | H6·H8 | `limit_external` | 없음 |
| 임의 URL 조회 도구 없음, 채팅 Markdown은 링크를 `<a>`로 만들지 않고 HTML을 글자로 표시 | 구조형 | H3(자동 로딩 유출) | D6-1, `frontend/src/chat/Markdown.tsx` | 테스트 |

판정형 가드레일(입력 분류기, 출력 필터, 쓰기 의도 검사)은 지금 없다.

## 4. 빈틈

1. **리마인더는 승인 없이 만든다**. 막는 장치가 프롬프트 지침뿐이다(H5).
2. **출처 경고는 표시만 한다**. 공격 메일에서 온 수신자가 경고와 함께 승인 화면에 오르면 사용자가 그대로 승인할 수 있다(H4). 경고 문구·화면이 실제로 오승인을 줄이는지 잰 적이 없다.
3. **공격 상황에서 측정한 값이 없다**. 데이터 봉투와 승인 흐름이 공격 성공률(ASR)을 얼마나 낮추는지, 공격이 원래 작업을 얼마나 망치는지 모른다(ADR-0018 결과 절, ADR-0033 목적).
4. **공격이 승인 화면까지 오는 비율을 모른다**. 승인 흐름이 H2는 막아도, 공격이 만든 쓰기 요청이 자주 뜨면 H4 위험과 사용자 피로가 커진다.

## 5. 후보 가드레일

| 후보 | 종류 | 줄이려는 피해 | 비용·위험 |
| --- | --- | --- | --- |
| 리마인더에 승인 흐름 적용 | 구조형 | H5 | 승인 단계가 하나 늘어 사용성이 떨어진다 |
| 외부 출처 수신자가 있는 발송은 추가 확인(수신자 직접 재입력 등) | 구조형 | H3·H4 | 정상 답장 흐름이 번거로워진다 |
| 프롬프트 인젝션 탐지기(도구 결과 입력) | 판정형 | H2·H4·H5·H6 | 메일 1통마다 호출 비용·지연. 정상 업무 메일 오탐. LLM 판정기면 판정기 자체가 속을 수 있다 |
| 쓰기 의도 검사기: 쓰기 호출 전 "사용자가 요청한 쓰기인가"를 판정 | 판정형 | H4 | 쓰기 호출마다 비용·지연. 오탐 시 정상 쓰기 차단 |

출시 차단 조건(H1·H2)은 구조형 장치로 보장한다. 판정형 후보는 구조형 장치를 대신하지 않고, 공격이 승인 화면까지 오는 횟수를 줄이는 보조 층으로만 검토한다.

## 6. 다음 단계

- ADR-0033 세트로 현재 장치의 기준선(S0)과 데이터 봉투·승인 흐름 ablation을 잰다. 세 지표(ASR, 공격 상황의 정상 작업 성공률, 정상 데이터 오탐률)를 함께 본다.
- 판정형 후보를 ablation 설정에 넣을지는 기준선 결과를 보고 정한다. 넣는다면 같은 세트에서 ASR 감소와 오탐률을 함께 보고한다.
- 측정 전에는 어떤 장치도 "공격을 막는다"고 쓰지 않는다.
