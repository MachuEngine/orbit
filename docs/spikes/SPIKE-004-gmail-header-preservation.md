# SPIKE-004 — Gmail 발송 시 앱이 넣은 헤더 보존

- 상태: 실행 준비 (실제 실행은 개발자가 직접 한다)
- 관련 결정: 세부 설계 D5-4(멱등성과 결과 불명 처리, 메일 발송 대조 방법)
- 기간: 1일
- 코드: `spikes/004-gmail-headers/` (스파이크용 코드이며 제품 코드로 쓰지 않는다)

## 확인할 질문

D5-4는 메일 발송 결과가 불명확할 때(응답 유실) 다시 보내지 않고 "보낸 메일함에서 앱이 넣은 고유 토큰을 찾아" 발송 여부를 확인하기로 했다. 이 방법이 되려면 다음이 성립해야 한다.

1. Gmail API(`users.messages.send`)로 보낼 때 앱이 지정한 `Message-ID`가 그대로 보존되는가.
2. 앱이 넣은 사용자 정의 헤더(`X-Orbit-Execution-Id`)가 보존되는가.
3. 보낸 메일함에서 그 값으로 메일을 **검색해서** 찾을 수 있는가. 찾을 수 있다면 발송 후 얼마 뒤부터인가.

## 실행 조건

- **실제 Gmail 계정과 OAuth 동의가 필요하다.** 개발자가 Google Cloud에서 OAuth 클라이언트(데스크톱 앱)를 만들고, 브라우저에서 직접 로그인·동의한다. Claude는 계정 생성, 로그인, 인증 정보 입력을 하지 않는다.
- **실제 메일을 발송한다.** 수신자는 개발자 본인의 테스트 주소로 한정한다. 발송은 개발자가 직접 실행한다.
- 인증 파일은 `secrets/` 아래에 둔다. 이 경로는 git에서 제외되고 Claude의 읽기 권한도 막혀 있다.
- 스코프: `gmail.send`, `gmail.readonly`. 둘 다 Google의 민감·제한 스코프이므로 OAuth 앱은 "테스트" 상태로 두고 본인을 테스트 사용자로 등록한다.

## 시나리오와 판정 기준

| ID | 구분 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| G1 | 검증 | 앱이 만든 `Message-ID`(`<uuid@orbit.invalid>` 형식)와 `X-Orbit-Execution-Id`를 넣어 본인에게 발송 → 응답의 Gmail 메시지 ID로 보낸 메일을 조회(`format=metadata`) | 두 헤더 값이 보낸 값과 같은지 기록 |
| G2 | 검증 | `rfc822msgid:<Message-ID>` 검색어로 보낸 메일함 검색 | 1건이 검색된다 |
| G3 | 관찰 | G2 검색을 발송 직후부터 일정 간격으로 반복 | 검색되기까지 걸린 시간 기록 (여러 번 발송해 분포 확인) |
| G4 | 관찰 | `Message-ID`를 지정하지 않고 발송 | Gmail이 만든 `Message-ID` 형식 기록 (대조용 키로 쓸 수 없는 경우 대비) |
| G5 | 관찰 | 사용자 정의 헤더 값으로 Gmail 검색이 되는지 | 검색 연산자로 찾을 수 있는지 기록 (일반적으로 임의 헤더는 검색 대상이 아니라고 알려져 있으나 확인) |

**가정이 성립했다고 보는 조건:** G1에서 `Message-ID`가 보존되고 G2에서 검색된다. 보존되지 않으면 `X-Orbit-Execution-Id`로 대조하는 대안(G1의 두 번째 값, 최근 보낸 메일 목록 조회 후 헤더 비교)을 검토한다.
