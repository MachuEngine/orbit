# ADR-0025 — 음성 입력(STT)과 음성 출력(TTS) v1

- 상태: 구조는 채택. STT 모델·TTS 방식은 `실험 중`(평가 계획의 음성 평가로 비교).
- 작성일: 2026-11-15
- 근거: ADR-0006(RLS 밖 저장소), ADR-0013(화면), ADR-0014·0015(OpenAI 직접 호출), ADR-0018(데이터 봉투), ADR-0024(데스크톱), D6-1(외부 콘텐츠), D9-3(모델 ID 고정)
- 사실 확인(2026-11-15, OpenAI 공식 문서): 권장 전사 모델 `gpt-transcribe`(약 0.0045달러/분, 파일 25MB, webm·ogg·wav 등). `whisper-1`·`gpt-4o-transcribe`·`gpt-4o-mini-transcribe`는 2027-02-26 종료 예정. 기존 TTS 모델(`tts-1`, `tts-1-hd`, `gpt-4o-mini-tts`)은 2027-01-06 종료 예정이고 Realtime API로 옮기라고 안내한다. AI 음성은 사용자에게 알려야 한다.

## 문제
손이 바쁘거나 다른 앱을 쓰는 중에는 타이핑으로 비서를 쓰기 어렵다. 음성은 세부 설계 D10-1의 선택 항목이었다.

## 결정

### 1. 방식: 계단식(STT → 기존 대화 → TTS)
- 음성을 글로 바꾼 뒤 지금의 대화 경로(`runflow`)에 그대로 넣는다. 승인 흐름, 데이터 봉투, 도구, 평가 스위트가 모두 그대로 적용된다.
- 음성끼리 바로 대화하는 Realtime API(음성 → 음성, 도구 호출 가능)는 승인·가드레일·평가 경로를 따로 만들어야 하므로 v1에 넣지 않고 비교 실험 후보로 둔다.
- 웹과 데스크톱 모두 같은 기능을 쓴다(데스크톱은 전역 단축키가 더해진다).

### 2. 음성 입력(STT)
- 켜고 끄기(토글): 마이크 버튼(또는 데스크톱 단축키)을 한 번 누르면 녹음을 시작하고, 다시 누르면 멈춘다(`MediaRecorder`, webm/opus). 사용자가 켠 동안에만 듣고, 항상 듣는 모드는 넣지 않는다.
- 녹음은 최대 60초이고 넘으면 자동으로 멈춘다. 멈추면 `POST /api/voice/transcribe`(multipart, 2MB 상한, `workspace_session` 안, CSRF 검사)로 보낸다.
- 서버는 새 인터페이스 `SpeechToText.transcribe(audio, *, language="ko") -> Transcript`로 전사한다. 구현은 OpenAI `gpt-transcribe`(모델 ID는 설정에서 고정, 별칭 금지), 테스트는 결정적 가짜 구현. 설정 지문에 STT 모델 ID를 넣는다.
- 결과 문장은 입력창에 채워 넣고 자동으로 보내지 않는다. 사용자가 고치거나 그대로 보낸다. 오인식이 바로 실행되지 않게 하기 위해서다(쓰기는 어차피 승인 필요).
- 브라우저 Web Speech API(`webkitSpeechRecognition`)는 쓰지 않는다. Electron에서는 이 API가 구글 음성 서버 키 없이 동작하지 않고, 브라우저마다 결과가 달라 평가로 재현할 수 없다.

### 3. 음성 데이터 처리
- 오디오 원본은 저장하지 않는다. 요청 처리 중 메모리에만 두고 전사 후 버린다. 로그에는 길이(초)·크기·오류 종류만 남기고 전사 문장은 남기지 않는다.
- 전사 문장은 사용자가 보낼 때만 일반 메시지로 저장된다(RLS).
- 오디오는 전사를 위해 OpenAI로 전송된다. 이미 답 생성과 임베딩에 같은 제공자를 쓰고 있어 새 수신자는 생기지 않지만, 개인정보 안내 문구에 음성 전송을 적는다.
- 남용 방지: 워크스페이스당 시간당 전사 횟수 상한(기본 60회)과 일일 총 녹음 시간 상한(기본 30분). 사용량(초)은 비용 기록에 남긴다.

### 4. 음성 출력(TTS)
- v1은 OS 내장 음성(`speechSynthesis`, macOS 음성)을 쓴다. 비용이 없고 답 문장이 밖으로 나가지 않는다. OpenAI 음성은 모델 종료 예정·Realtime 이전 안내가 있어 비교 실험 후보로만 둔다.
- 각 답에 "읽어 주기" 버튼을 둔다. 음성으로 질문했을 때는 답을 자동으로 읽는 설정(기본 꺼짐)을 둔다.
- 읽는 범위: 비서의 최종 답 문장만 읽는다. 도구 결과·메일·문서 원문은 읽지 않는다. 마크다운 기호, 코드, 주소 형태 문자열, 작업 집합 핸들(M3, E1)은 빼고 읽으며, 600자를 넘으면 앞부분만 읽고 "나머지는 화면에서 확인하세요"로 끝낸다.
- 승인 요청 카드는 읽지 않는다. 승인은 화면에서 보고 누르게 한다(음성으로 승인하지 않는다).

### 5. 화면
- 입력창에 마이크 토글 버튼. 켜진 상태가 분명히 보이게 한다(버튼 상태 `aria-pressed`, 녹음 중 표시, 경과 시간). 다시 누르면 멈추고 전사, Esc는 전사 없이 취소. 접근성 이름을 붙이고 키보드로 쓸 수 있게 한다. 전사 결과는 입력창 텍스트로 들어가므로 한글 IME와 충돌하지 않는다.
- 마이크 권한이 없거나 거부되면 안내 문구를 보인다. 웹은 HTTPS 또는 localhost에서만 녹음할 수 있다.

### 6. 평가 (평가 계획 초안에 추가)
- STT 정확도: 한국어 문자 오류율(CER), 고유명사(사람·프로젝트 이름) 정확도. 데이터는 평가 문항 발화를 여러 OS 음성으로 합성한 오디오와 개발자가 직접 녹음한 소량 세트. 합성 오디오는 실제 발화보다 쉬울 수 있다는 한계를 적는다.
- 음성 종단: 같은 과제를 텍스트와 음성 입력으로 냈을 때 과제 성공률 차이.
- 지연: 녹음 종료부터 전사 완료까지, 질문부터 첫 음성까지(p50·p95). 비용: 분당 비용.
- 비교 후보: STT 모델 간, 계단식 vs Realtime 음성 대화, OS 음성 vs OpenAI 음성(청취 선호, 사람 평가).

## 보류
- 항상 듣기·호출어, 음성 승인, 대화 모드(말을 멈추면 자동 전송), 음성 대화(Realtime), 다국어.

## 검토한 대안
| 대안 | 채택하지 않은 이유 |
| --- | --- |
| Web Speech API로 STT | Electron에서 동작하지 않고 결과를 재현할 수 없다 |
| Realtime 음성 대화로 시작 | 승인·데이터 봉투·평가 경로를 새로 만들어야 한다. 비교 실험으로 다룬다 |
| OpenAI TTS 먼저 | 비용, 답 문장 외부 전송, 모델 종료 예정 |
| 전사 후 자동 전송 | 오인식이 그대로 실행된다. v1은 확인 후 전송 |
| 오디오 원본 저장(재평가용) | 음성은 민감 정보다. 평가용 오디오는 합성·개발자 녹음 데이터로 따로 둔다 |
