# ADR-0030 — Agent 패턴 비교용 평가 변형

- 상태: 채택 (2026-11-16 개발자 지시: 계획한 비교 평가를 모두 진행. 패턴 선택 결과는 측정 후 별도 결정)
- 작성일: 2026-11-16
- 근거: 평가 계획 §2 "Agent 패턴(Fixed Workflow, ReAct, Plan & Execute)", ADR-0023(runflow 평가 대상), ADR-0012(승인), ADR-0006(그래프 상태)

## 문제
평가 계획의 패턴 비교를 하려면 같은 도구·같은 승인 흐름·같은 모델에서 제어 방식만 다른 변형이 필요하다. 지금 실사용 경로(`runflow`)는 ReAct 한 가지다.

## 결정
- 세 패턴을 `runflow` 그래프의 평가 전용 변형으로 만든다. 실사용 경로(워커·API)에서는 켜지 않는다. 끈 상태의 도구 목록·프롬프트·요청·설정 지문은 지금과 같다(`eval_variants`와 같은 원칙).
- 공통: 도구 구현, 데이터 봉투, 승인 interrupt, 쓰기 실행 규칙, 답 제출 안내(eval-answer-v2), 에피소드 예산은 그대로다. 패턴 이름과 버전을 설정 지문에 넣는다.

| 패턴 | 정의 |
| --- | --- |
| `react` | 지금의 runflow(모델이 매 단계 도구를 고르고 결과를 보고 다음 행동을 정한다) |
| `plan_execute` | 첫 단계에서 도구 없이 계획(번호 붙은 단계 목록)을 한 번 만든다. 이후 실행 단계는 계획을 맥락에 둔 채 도구를 쓴다. 도구 오류가 나면 한 번 다시 계획한다 |
| `fixed_workflow` | 첫 단계에서 의도를 정해진 범주(일정 조회, 메일 질의, 문서 질의, 일정 쓰기, 메일 답장, 리마인더, 기타) 중 하나로 분류한다. 범주마다 코드로 정한 도구 부분집합과 단계 상한, 범주별 지시문으로만 진행한다. 분류는 다시 하지 않는다 |
- `fixed_workflow`는 범주별 도구 순서를 코드가 완전히 정하는 대신 "범주별 고정 도구 집합 + 단계 상한"으로 근사한다. 인자 추출까지 코드로 고정하면 범주마다 별도 구현이 필요해 이번 범위를 넘는다. 이 근사를 보고서에 적는다.
- 계획·분류 문장은 그래프 상태에 넣지 않고 에피소드 메모리에만 둔다(ADR-0006). 평가 결과 기록에는 남긴다(ADR-0029).

## 영향
- 패턴 비교는 같은 모델(기준 모델)·dev 분할에서 먼저 하고, 결정에 쓸 비교만 test로 한 번 확인한다.
- 안전 세트가 없어 계획의 §1-5 지표는 이번 패턴 비교에 포함하지 않는다.
